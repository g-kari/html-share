01　会社として取り組む場合

会社・学校・団体などの管理者が、従業員の業務用アカウントと端末を管理する方式。BYOD（従業員の私物）と会社所有端末では、登録方法とデータ消去の権限が異なる。管理対象の端末台数だけでなく、利用者ごとのライセンス、端末の所有形態、実際の登録方式をそろえて判断する。以下は一般企業向けの商用プラン例であり、学校や非営利団体ではEducation・Nonprofitsなどの別エディションも確認する。[1][7]

  1. 管理対象と責任範囲を決める従業員・部署・端末を棚卸しし、個人所有か会社所有かを区別する。BYODでは管理できる情報、業務領域、紛失時の処理を本人に説明する。
  2. 組織アカウントと契約プランを準備する管理者アカウント、ドメインの確認、利用者のライセンス、組織部門（OU）を整える。既存のMDM・EMM製品との競合も調べる。
  3. 段階的に登録するAndroidの基本／詳細管理、WindowsのEndpoint Verification・GCPW・Windows MDMを目的別に設定する。先に試験OUと試験端末で検証する。
  4. 継続運用する端末の登録状況、ポリシー適用、回復キー、紛失時のワイプ対象、退職・機種変更時の解除手順を管理する。

02　個人で取り組む場合

個人利用は「個人Googleアカウントで自分の端末を守る」場合と、「個人事業主・1人運用者が管理組織を作る」場合に分かれる。前者の操作画面はGoogle Workspace管理コンソールではない。[22]

個人のGmailだけで自分の端末を管理する

Google WorkspaceやCloud Identityの契約は不要。Androidの標準機能、Googleアカウントのセキュリティ設定、Windowsの標準セキュリティ機能で自分の端末を保護する。一方、組織管理のWindows MDM・GCPW・Android Enterpriseの仕事用プロファイルを、通常の個人Gmailアカウントだけで設定することはできない。[22][29]

端末と目的個人向けの方法Google Workspace管理との違い
自分のAndroidを紛失したFind Hubで位置確認・ロック・消去。端末の電源、接続、アカウント、設定などの条件あり本人による紛失対応。組織の端末台帳・アプリ配布・業務用ワイプではない
自分のWindowsを保護するWindows セキュリティ、OS更新、必要に応じてMicrosoftアカウントの「デバイスを探す」を設定する個人向けOS機能。Google管理コンソールからBitLockerやWindows Updateのポリシーを配布する方式ではない
子どものAndroidを管理する適用条件を満たす場合はFamily Linkでアプリ・利用時間などを管理する保護者による監督機能。従業員の端末管理やWindows MDMの代替ではない

公式資料：Find Hub、Family Link、Windows標準機能。Google Workspace Individualは個人GoogleアカウントにMeet・Gmail・カレンダー等の追加機能を提供する別契約であり、この記事の企業向け端末管理ライセンスとして数えない。[25]

個人事業主・1人運用でGoogleの端末管理を使う

本人が組織の管理者と端末の利用者を兼ねる方式。Cloud Identityの新規登録では、ドメインの所有権を証明できることが条件。個人Gmailに管理権限を後付けするのではなく、管理対象のGoogleアカウントを別に用意する。Googleの案内は事業用ドメインを前提としているため、趣味の個人利用も同条件で契約できるかどうかは、登録時の利用資格・規約で確認する。[23][24]

  1. 目的から契約を決める端末とアカウントの基本管理ならCloud Identity Free。業務メール等も使うならBusiness Starter。仕事用プロファイルやWindows MDMまで必要ならCloud Identity PremiumまたはBusiness Plusなどを検討する。
  2. ドメインと管理者アカウントを用意するCloud Identityは申込時に所有するドメインを指定する。管理コンソールで確認用のDNS TXTレコードを取得し、ドメインのDNSに設定して所有権を証明する。Cloud Identity FreeにはGmailメールボックスが付かないため、管理者宛ての通知を受け取れる外部メールサービスか転送先も用意する。
  3. 本人の管理対象アカウントで端末を登録する対象アカウントに必要なライセンスを付与し、Androidでは基本／詳細管理、WindowsではGCPWまたはWindows MDMの対応要件を確認して登録する。個人Gmailとは別のアカウントとして扱う。
  4. 自分の私的データを保護する試験端末でポリシーを確認する。自分のAndroidをBYODとして仕事用プロファイルに分離する場合と、完全管理端末として登録する場合では、消去できる範囲が異なる。

07　Android端末の登録と管理

Androidの基本管理は、業務用アカウントを追加するだけで始められる場合がある。仕事用プロファイル、Managed Google Playによるアプリ管理、ゼロタッチ登録には詳細管理を利用できるライセンスと設定が必要になる。[5]

以下は会社・団体、または個人事業主が管理対象のGoogleアカウントを発行している場合の手順。通常の個人Gmailだけの端末管理は個人利用の節を参照する。

  1. 管理方式を決める基本／詳細、BYOD／会社所有を分類
  2. ポリシーを設定管理コンソールで対象OUと管理レベルを設定
  3. 端末を登録管理対象Googleアカウントでサインイン
  4. 適用を検証Work Profile・アプリ・端末一覧を確認
管理者：基本管理／詳細管理を設定する
  1. 管理コンソール admin.google.com に適切な権限でログインし、対象利用者と所属組織部門（OU）を確認する。
  2. 端末 → モバイルとエンドポイント → 設定 → ユニバーサル → 全般 → モバイル管理を開く。
  3. 基本管理のみなら「基本」を選択。詳細管理の対象者は「カスタム」を選んでAndroidを「詳細」に設定する。すべてのOSをまとめて詳細管理にするとAppleのプッシュ証明書を要求する場合があるため、Androidのみならカスタム設定が適する。
  4. 画面ロック、パスコード、業務アプリ、端末承認、ワイプ権限などをOU別に設定する。
  5. 利用者に設定手順と管理される範囲を説明し、試験端末で登録・削除動作を確かめる。

契約がBusiness StarterやCloud Identity Freeなら、UI上で詳細管理を選んでも対象ユーザーへの高度な機能が使えるわけではない。Google管理アプリ（Android Device Policy）は登録フローの案内に沿って導入する。[6]

組織のBYOD：従業員などの私物Androidに仕事用プロファイルを作る
  1. 管理者が対象OUにAndroid詳細管理を有効化し、対象ユーザーに対応ライセンスを付与する。
  2. 利用者がAndroidの「設定 → パスワードとアカウント」等から業務用Googleアカウントを追加する。機種により画面名は異なる。
  3. 表示される管理ポリシーと権限を確認し、Android Device Policyの案内に従って仕事用プロファイルを作成する。
  4. 「仕事用」のアプリ領域から会社アカウントで利用し、個人用領域とデータの保存先が分かれているか確認する。
  5. 管理者が端末一覧の登録状態・所有形態・最終同期・ポリシー適用を確認する。

Work Profileは業務アプリ・仕事用データと個人用の領域を分ける。管理者による「アカウントをワイプ」は原則として仕事用プロファイルを削除し、個人の写真や私的アプリを残す。基本管理だけではこの分離は行われない。[7][11]

会社所有端末：業務専用モードとゼロタッチ登録
  1. 会社所有端末の購入・棚卸しを行い、業務専用（Fully managed）か、対応する個人利用許可モードかを決める。端末・Androidバージョンと管理要件によって対応可否が変わる。
  2. 対応ライセンスとAndroid詳細管理を準備。ゼロタッチを使う場合は、対応する端末を認定販売店経由で用意する。
  3. 管理コンソールの 端末 → モバイルとエンドポイント → 登録 → Androidゼロタッチ登録で販売店側のゼロタッチアカウントと連携し、既定の登録構成とサポート連絡先を設定する。
  4. 新規端末の初期セットアップ、または初期化後のセットアップで自動登録を実施する。
  5. 管理者が所有形態、端末ポリシー、業務アプリ、ワイプできる範囲を確認する。

ゼロタッチ登録は管理画面の設定だけで既存の利用中端末を無停止で取り込める機能ではない。登録の適用により端末の初期化が発生する場合があり、公式資料は既存端末について警告している。事前に利用者へ通知し、バックアップと業務停止時間を確保する。[8]

08　Windows端末の登録と管理

Windowsでは「端末が見える」「Googleでログインできる」「OSの設定を強制できる」の3つは別の機能。GCPW単体だけで端末暗号化や更新ポリシーの強制は行えない。OSポリシーが目的ならWindows端末管理への登録を確認する。[10]

以下は管理対象アカウントを用いる組織・1人事業者向け。個人のWindowsを普通のGoogleアカウントで使う場合は個人向けの標準機能を参照する。GCPWのWindows Home非対応など、OS側の要件も先に確認する。

Endpoint Verification：まず端末の状態を把握する
  1. 管理者がエンドポイント確認を使う対象ユーザー・ブラウザ・配布方式を決める。
  2. WindowsのChromeにEndpoint Verification拡張機能を配布し、必要なコンパニオンアプリを導入する。公式クイックスタートではChrome 110以降を対象とする。
  3. 管理対象GoogleアカウントでChromeにログインし、端末情報が管理コンソールのエンドポイント一覧に表示されるか確認する。
  4. 暗号化・OS・画面ロック等の取得できた情報をポリシー評価に使う。Context-Aware Accessを実際に設定する場合は、その機能に対応した別ライセンスが必要になる。

Endpoint Verificationそのものは基礎的な端末管理機能。端末情報を収集しても、Windows MDMのBitLocker設定や更新設定が自動的に配布されるわけではない。[14]

GCPW：GoogleアカウントでWindowsにログインする

対象：Windows 10/11のPro、Pro for Workstations、Enterprise、EducationなどGoogleが示す対応エディション。Windows HomeとARM版は対象外。インストールにはローカル管理者権限が必要で、Chromeの対応バージョン等も満たす必要がある。[12]

  1. 管理者がGoogle管理コンソールからGCPWのインストーラーを取得する。管理コンソールからの配布物に付く組織向けトークンと許可ドメインの設定を確認する。
  2. 既存ローカルWindowsプロファイルをGoogleアカウントへ関連付ける必要がある場合は、ユーザーデータの移行方針を先に決める。
  3. 対象PCへGCPWをインストールする。Windowsログイン画面のGoogleアカウントによるサインインを選択する。
  4. 管理対象アカウントで認証し、設定済みの2段階認証を完了する。
  5. 管理コンソールの登録情報と、Windowsログイン、既存アカウントとの対応付けを確認する。

GCPW単体はBusiness StarterやCloud Identity Freeにも含まれる。一方、OSのポリシーを配布するWindows MDMはBusiness Plus、Enterprise Standard / Plus、Cloud Identity Premiumなどの対象ライセンスが必要。[2]

Windows MDM：BitLocker・Windows Update・管理者権限を制御する
  1. 管理対象ユーザーの契約がBusiness Plus、Enterprise Standard / Plus、Cloud Identity Premiumなどに該当するか確認する。
  2. 管理コンソールで 端末 → モバイルとエンドポイント → 設定 → Windows → Windows管理の設定を開く。Windows端末管理は初期状態で無効のため、対象OUを選び有効化する。
  3. 暗号化（BitLocker）、更新プログラム、ローカルユーザー権限、画面ロック、カスタムOMA-URI（対応ポリシーに限る）などの設定をテストOUで作成する。
  4. GCPW連携を使う場合はWindows端末の自動登録の設定を確認する。対応ユーザーがGCPWでログインすると自動登録される構成にできる。
  5. GCPWを使わない場合はWindows側のChromeまたはEdgeで https://deviceenrollmentforwindows.googleapis.com/v1/deeplink を開き、画面案内で職場アカウントを登録する。
  6. 管理コンソールの 端末 → 概要 → エンドポイント などで対象の管理方式と最終同期を確認し、実機でポリシー強制を検証する。

Windows端末管理では、同一デバイスでMDMに登録するユーザーは原則1人で、最初に登録したユーザーの端末ポリシーが他のWindowsユーザーにも影響する。GCPWの複数ユーザーでのログイン機能と区別する。[13][15]

リモートデバイスワイプはWindowsの業務データだけを安全に分離削除する操作とは限らず、端末内の個人データも含めて消去する。検証用端末と、所有形態に応じた承認フローを用意する。[11]

Chrome Enterprise Core：ブラウザだけを集中管理する場合

Chrome Enterprise Coreはブラウザのクラウド管理の無料枠。Google Workspaceの上位プランを購入しなくても、対応する管理用組織の設定とChromeの登録によってブラウザポリシーを配布できる。[16]

  • 設定できる例：拡張機能の許可・禁止、ブラウザ更新、Webアクセス、セキュリティポリシー。
  • 別の領域：Windowsのユーザーログオン、BitLocker・Windows Update・USB制限などのOS管理。
  • 端末全体が管理対象か、Chromeブラウザだけを管理しているかを登録一覧で区別する。

09　遠隔削除・ポリシーと運用上の制限

ワイプは最も誤解しやすい操作。管理コンソールに同じ「アカウントをワイプ」「端末をワイプ」と表示されても、OSや登録モードで消去範囲が変わる。[11]

端末・登録方式業務アカウントの削除端末全体の初期化利用者への影響
Android個人所有・仕事用プロファイル仕事用プロファイルを削除管理者の「端末ワイプ」対象ではない原則として個人用領域は残る
Android会社所有・業務専用管理操作によっては端末全体が初期化利用可能端末内の個人データも消える可能性がある
Android個人所有・仕事専用登録仕事用アカウントの削除が全体初期化につながる場合がある登録形態による「個人所有」だけで安全な部分削除とは判断できない
Windows GCPW単体Googleアカウントの解除・ログイン制御の範囲を確認Windows MDMの端末ワイプ機能は含まれないローカルに残るデータの扱いは別管理
Windows MDM機能別にGoogleアカウント情報を制御端末ワイプに対応OSの初期化によりローカルデータが失われる

アカウントワイプは、Drive for desktopでローカルにミラーされたファイルまで必ず消す操作ではない。オフライン保存・私的アプリ・同期済みコピーが残る可能性があるため、DLP、ストレージ暗号化、アカウント無効化などを別途設計する。[11]

  • 実契約エディション、ユーザーのライセンス割当、端末OSバージョン、既存EMM、管理者の権限、設定済み組織部門は未確認。

  • 本記事は実機を登録していない。端末ワイプなど取り返しのつかない操作は試験端末で検証する。
