Windows・Android端末管理

管理範囲、登録方法、Googleの各管理機能の違いを整理する。

Google公式資料に基づく解説 ｜ 確認：2026年11月13日 ｜ 実機登録は未検証

結論：Androidは業務プロファイルと端末管理を一体的に構成できる。Windowsは「端末確認」「OSログイン」「端末ポリシー」「ブラウザ制御」を別々に設計する。

03　Android端末を登録する

  1. 管理方式を決める基本／詳細、BYOD／会社所有を分類
  2. ポリシーを設定管理コンソールで対象OUと管理レベルを設定
  3. 端末を登録管理対象Googleアカウントでサインイン
  4. 適用を検証Work Profile・アプリ・端末一覧を確認
個人所有（BYOD）の登録手順
  1. 管理者が対象組織部門に基本管理または詳細管理を設定する。
  2. 利用者がAndroidに業務用Googleアカウントを追加する。
  3. 詳細管理では表示された案内に従い、仕事用プロファイルの作成と管理権限への同意を行う。
  4. 管理コンソールに登録され、仕事用アプリが分離されていることを確認する。
会社所有端末の登録手順
  1. 業務専用・個人利用許可など運用モードを決める。
  2. 利用可能な登録方式（QRコード、ゼロタッチ登録等）を確認する。
  3. 新規セットアップ時に指定方式でプロビジョニングする。
  4. アプリ・ポリシー適用を検証する。

既存端末の再登録では初期化が必要になる方式がある。作業前にバックアップを確認。

04　Windows端末を登録・管理する

Endpoint Verification
  1. 管理者がエンドポイント確認とアクセス制御の要件を設定する。
  2. Windows 10/11のChromeにEndpoint Verification拡張機能を導入する。
  3. 必要に応じてネイティブヘルパーをインストールする。
  4. 管理対象GoogleアカウントでChromeにログインし、端末情報が表示されることを確認する。

これだけでWindows OS全体のMDM管理が有効になるわけではない。

GCPWでWindowsにログインする
  1. 管理者がGCPWを構成し、既存Windowsプロファイルとの関連付けを検討する。
  2. 対象PCにGCPWをインストールする。
  3. 初回はインターネット接続を用意し、Windowsサインイン画面から仕事用アカウントを選ぶ。
  4. Googleアカウント・必要な二段階認証を完了する。

公式条件ではChrome 81以降が必要。AD参加端末は追加の条件がある。

Windows MDMポリシーを配布する
  1. 契約エディションでWindows端末管理を使用できるか確認する。
  2. 管理コンソールの「端末 → モバイルとエンドポイント → 設定 → Windows」からポリシーを用意する。
  3. 指示された職場／学校アカウント登録フローでWindows端末を登録する。
  4. Windowsの管理状態と管理コンソールの端末一覧を照合する。

正確な登録画面・自動登録条件は対象エディション・環境で要検証。

05　契約・運用の注意

  • 基本的なエンドポイント管理は多くのGoogle Workspace／Cloud Identityプランに含まれる。詳細管理・エンタープライズ管理の利用範囲はプラン別に確認する。
  • Android詳細管理と第三者EMMの併用には制約がある。既存MDMがあれば管理主体を確認する。
  • 個人所有端末と会社所有端末は組織部門・管理ポリシー・削除権限を区別する。
  • 実際の契約エディション、既存MDM、OSバージョン、管理者権限は未確認。本稿の登録画面は現物検証していない。
