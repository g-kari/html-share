Google WorkspaceのWindows・Android端末管理

登録手順、できること・できないこと、運用上の判断を整理

公式ヘルプ確認：2026年11月13日／機能は契約エディション・OS・管理方式によって異なる

結論：AndroidはAndroid Enterpriseを通じて業務領域・アプリ・端末ポリシーを幅広く管理できる。Windowsでは「端末情報の確認」「Googleアカウントによるサインイン」「Windows MDMポリシー」「Chrome管理」は別の機能。Windows全体の管理をChrome管理だけで代替することはできない。

1. 最初に選ぶ管理方式

Windows

Endpoint Verification

端末情報を取得し、デバイスベースのアクセス制御を支援する。Chromeの拡張機能や必要に応じてヘルパーを利用。

Windows

GCPW

Google WorkspaceアカウントでWindowsにサインイン。既存Windowsプロファイルとの関連付けにも対応。

Windows

Windows端末管理

対応エディション・端末でWindows MDMポリシーを配布。カスタムOMA-URIによる設定も可能。

Android

Google endpoint management

基本管理と詳細管理を選択。Work Profile、Managed Google Play、企業所有端末は管理方式に応じて使用。

3. Androidの登録方法

① 管理方式を決定基本管理／詳細管理、BYOD／企業所有
② 管理コンソールで有効化端末 → モバイルとエンドポイント → 設定
③ 端末を登録Google管理アカウントでサインインし、案内に従う
④ 適用を確認端末一覧・業務プロファイル・アプリの状態
個人所有端末（BYOD）の手順
  1. 管理者は対象の組織部門で適用する管理レベルを選び、必要なアプリ・ポリシーを設定する。
  2. 利用者はAndroid端末に会社の管理対象Googleアカウントを追加する。
  3. 詳細管理では表示される登録手順に従い、仕事用プロファイルの作成と管理への同意を行う。
  4. 仕事用アプリが仕事用プロファイルに入り、管理コンソールから端末を確認できることを検証する。

端末OS・既存管理状態により画面は異なる。実機画面での確認は未実施。

会社所有端末（専用端末・個人利用許可端末）
  1. 会社所有としての登録方式（QRコード、ゼロタッチ登録等）と利用形態を決める。
  2. 管理コンソール側で組織・ポリシー・Managed Google Playの設定を整える。
  3. 新規セットアップ時に対象の登録方式でプロビジョニングし、ポリシーと業務アプリが反映されることを確認する。

既存端末の再登録では初期化が必要になる方式がある。初期化やワイプは事前にバックアップと所有者確認を行う。

4. Windowsの登録方法

目的を先に選ぶ。ブラウザ制御だけならChrome管理、端末の姿勢確認ならEndpoint Verification、GoogleアカウントでWindowsにログインしたいならGCPW、OS設定管理ならWindows端末管理を検討する。
A. Endpoint Verificationを導入する
  1. 管理者が端末確認と必要なアクセス制御を構成する。
  2. Windows 10/11のChromeにEndpoint Verification拡張機能をインストールする。
  3. 要求される環境ではネイティブヘルパーをインストールする。
  4. 管理対象GoogleアカウントでChromeにサインインし、端末情報の収集を確認する。

これだけでWindows全体のMDM管理が有効になるわけではない。

B. GCPWでWindowsにサインインする
  1. 管理者がGCPWを構成して対象PCへインストールする。既存ローカル・ADプロファイルとの関連付けを事前に計画する。
  2. 最初のサインイン時はインターネット接続を用意する。
  3. Windowsサインイン画面から「仕事用アカウントを追加」または既存アカウントを選択する。
  4. Googleアカウント認証と必要な二段階認証を完了し、利用者プロファイルを確認する。

Google公式では初回サインインにChrome 81以降とインターネットが必要とされる。AD参加時は追加条件がある。

C. Windows端末管理（MDM）を使う
  1. 契約エディションにWindows端末管理機能があるか確認する。
  2. 管理コンソールの 端末 → モバイルとエンドポイント → 設定 → Windows で対象の組織部門・ポリシーを準備する。
  3. Windowsの職場/学校アカウント登録画面で、管理者が指示する組織アカウントによる接続・登録を進める。
  4. Google管理コンソールのデバイス一覧とWindows側の管理状態で登録・ポリシー適用を確認する。

登録画面・自動登録の条件はエディション、Windowsの状態、GCPW導入構成に依存。正確な画面遷移は対象環境で要検証。

5. エディションと運用の注意

  • 基本的なエンドポイント管理は多くのGoogle Workspace／Cloud Identityエディションに含まれるが、詳細管理とエンタープライズ管理には上位プランが必要になる場合がある。
  • Android詳細管理はサードパーティEMMとの併用制約がある。既存のIntune等を使う場合は管理主体を先に設計する。
  • Windows向けのポリシーとAndroid向けWork Profileは異なるアーキテクチャ。機能名だけで同等とみなさない。
  • 業務端末と個人端末は組織部門や登録ポリシーを分け、ワイプ権限・対象範囲を事前確認する。
  • 本稿は一般的な管理仕様の解説。利用中の契約エディション、既存MDM、実機OS、管理者権限は未確認。
