GitHub Teamでセキュリティリスク評価が自動実行に

出典：GitHub Changelog「Security risk assessments run automatically on GitHub Team」（2026年11月18日）
あわせて公式ドキュメントと公式FAQで対象と条件を確認した。確認日：2026年11月20日

要点
  1. GitHub Teamプランの組織では、セキュリティリスク評価が自動で実行されるようになった。GitHub Changelogで2026年11月18日に発表された。
  2. 評価は2種類ある。secret risk assessmentは組織の全リポジトリを対象に漏れた認証情報を調べ、code security risk assessmentは最大20件のリポジトリを対象にコードの脆弱性を調べる。どちらも無料で使える。
  3. 結果を見られるのは組織の管理者とセキュリティマネージャーである。結果は組織の現在のリスクを把握し、次に対処するものの優先順位を決める材料になる。

結論：何が変わったか

GitHub Changelogの2026年11月18日の記事は、GitHub Teamプランの組織でセキュリティリスク評価が自動で実行されるようになったと伝えている。発表文の冒頭は次のとおりである。

“GitHub security risk assessments now run automatically for organizations on GitHub Team.”

これまでもリスク評価自体はGitHub TeamとGitHub Enterprise Cloudの組織で使えた。今回の変更で、Teamプランの組織では評価が自動で実行されるようになった。組織の管理者とセキュリティマネージャーは、無料の評価の結果を確認して、漏れた認証情報とコードの脆弱性を見つけ、組織の現在のリスクを把握し、次の手の優先順位を決められる。

対象：プランと見られる人

対象はGitHub Teamプランの組織である。公式ドキュメントでは、リスク評価を使えるのはGitHub TeamまたはGitHub Enterprise Cloudの組織の管理者（organization owners）とセキュリティマネージャーとされている。code security risk assessmentはGitHub Enterprise Server 3.23にも入っている。

結果の確認は組織のページの「Security and quality」タブから「Assessments」を開いて行う。再実行はレポート右上の「Rerun scan」から行う。

評価は2種類ある

secret risk assessmentは、組織の全リポジトリを対象に、コードに埋め込まれた認証情報を探す。対象はAPIキー、トークン、パスワードなどの認証情報で、プロバイダーごとのパターンと汎用パターンの両方で検出する。レポートには検出されたシークレットの総数、種類ごとの分布、どのリポジトリに出ているかがまとまる。結果はリポジトリの処理が進むにつれて順次表示される。

code security risk assessmentは、選んだ最大20件のリポジトリをCodeQLでスキャンし、コードの脆弱性を調べる。対象リポジトリは変更でき、既定では直近90日にコミット活動が最も多いリポジトリが選ばれる。結果には深刻度ごとのリスクがまとまり、Copilot Autofixで修正を速められる箇所も示される。結果はスキャン全体が終わってから表示される。

評価対象調べるもの結果の出方
secret risk assessment組織の全リポジトリ漏れた認証情報（APIキー、トークン、パスワードなど）処理が進むにつれて順次表示
code security risk assessment選んだ最大20件のリポジトリ（CodeQLでスキャン）コードの脆弱性（深刻度別）スキャン全体の終了後に表示

結果で分かること

2種類の評価を合わせると、組織の状態が点検できる。漏れた認証情報がある場合はその総数と種類、出ているリポジトリが分かる。コードに脆弱性がある場合はその深刻度と対象リポジトリが分かる。あわせて、組織の現在のリスクの全体像と、次に優先して対処すべきものが見える。

問題が見つからなかった場合は、現在の対策が機能していることの裏付けになる。GitHubは、結果と連絡先が営業チームに共有されるのは本人が同意した場合だけであり、同意しなければアカウントチームには評価を実行したことだけが伝わると説明している。

費用・所要時間・再実行の間隔

評価は無料である。コードスキャンに使うGitHub Actionsの分数も課金されない。評価の期間中にGitHub Code SecurityやSecret Protectionのライセンス料も発生しない。

多くのスキャンは30分以内に終わる。組織が大きい場合はそれ以上かかることがある。レポートの準備ができるとGitHubからメールで通知される。

再実行は90日に1回までである。再実行のたびに、スキャン対象のリポジトリを選び直せる。

結果を見たあとの選択肢

結果を確認したあとは、評価の画面からSecret ProtectionやCode Securityを有効化できる。対象の企業管理者は評価からGitHub Advanced Securityの試用を直接始めることもできる。どれも任意であり、評価を受けただけで課金は始まらない。

注意点

  • リスク評価は既存のコードスキャンのアラートには影響しない。評価は別の経路でアップロードされ、既存のアラートを変更したり妨げたりしないと公式FAQに書かれている。
  • 評価は時点のスナップショットである。90日に1回までしか再実行できないため、継続的な検出が必要な場合はSecret ProtectionやCode Securityの有効化が別途必要になる。
  • この記事の内容は2026年11月20日に公式Changelogと公式ドキュメントで確認したものである。自動実行の対象や条件が変わる可能性があるため、実行前に公式ドキュメントを確認してほしい。
