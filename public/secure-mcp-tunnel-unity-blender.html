Secure MCP Tunnel

WindowsのUnity・Blenderをクラウドから操作する設定手順

2026年10月3日確認 / 個人用・非公開接続

これは設定手順です。PCへのインストール・Tunnel作成・接続検証が実行済みという意味ではありません。例のID・保存先は実際の値へ置き換えてください。

1. 接続の全体像

OpenAI公式のSecure MCP Tunnelを使う。Windows PC上のtunnel-clientがOpenAIへ外向きHTTPS接続を作るため、ルーターのポート開放やUnity・Blenderの公開URLは不要。[1]

Unity：OpenAI → Unity用Tunnel → PCのtunnel-client → 127.0.0.1:8080/mcp → Unity Editor

Blender：OpenAI → Blender用Tunnel → PCのtunnel-client → stdio MCPサーバー → localhost:9876のTCP → Blender

Blenderの9876番はHTTP MCPではない。tunnel-clientにstdioサーバーを起動させる。UnityとBlenderには別々のtunnel_idを割り当て、tunnel-clientは各IDにつき1プロセスにする。[2]

必要なもの

・Unityの対象プロジェクトとBlenderの作業ファイルをバックアップ
・Unity側：Git、uv、Python 3.10以上、MCP for Unity
・Blender側：Blender 3.0以上、uv、Python 3.10以上、MCP for Blender
・OpenAI PlatformのTunnel利用権限とruntime API key
・接続先でDeveloper modeとTunnel接続を作成できる状態

Unity・Blenderのバージョン

Unity 2022.3系のVRChatプロジェクトはその版とBuilt-in設定を維持する。本手順は非公式のCoplayDev/MCP for Unity v10.2.0を使う。Unity 2021.3 LTS以上が対応範囲。[3] Unity Technologies公式MCPはUnity 6以上とAI Assistant等が条件なので、今回の接続のためだけに更新しない。[4]

Blenderは非公式のahujasid/mcp-for-blender 2.1.3を使う。Blender Lab公式MCPとは別製品で、アドオンとサーバーを混ぜない。[5]

先に守ること

接続するとPythonやC#経由で強力な編集・コード実行が可能になる。Tunnelは通信経路を保護するが、PC内の実行をサンドボックス化しない。管理者として起動しない。専用Windowsユーザーや検証用コピーを使い、秘密・個人資料を同じ実行環境に置かない。すべての待受をloopbackに限定し、最初は読むだけの確認から始める。

2. OpenAI側とWindowsの準備

2-1. 先に利用画面を確認する

OpenAI PlatformのTunnels管理を開く。ここが使えることと、ChatGPTのDeveloper mode/Tunnel接続が使えることは別条件。[1][2]

Tunnels管理
https://platform.openai.com/settings/organization/tunnels

管理者にはTunnels Read + Manage、実行用にはRead + Useが必要。Tunnelに自分のPlatform organizationと実際に使うChatGPT workspaceを関連付ける。個人organizationだけでは別workspaceに自動表示されない。[1]

Unity用とBlender用の2つのTunnelを作成し、返されたtunnel_idを控える。以下のTUNNEL_UNITY / TUNNEL_BLENDERは、その実IDに置き換える。IDは通常tunnel_に32桁の小文字16進数が続く。[2]

2-2. runtime keyは本人が作成する

Runtime API keys
https://platform.openai.com/settings/organization/api-keys

Restrictedを選び、Tunnels Read + Useに絞る。長期稼働プロセスへAdmin keyを渡さない。キーはチャット、Git、plugin package、画面キャプチャに貼らない。[2]

2-3. Windows版tunnel-clientを取得

公式の最新リリース
https://github.com/openai/tunnel-client/releases/latest

確認時点の最新はv0.0.15。Intel/AMD PCはtunnel-client-v0.0.15-windows-amd64.zip、Windows ARMはwindows-arm64.zipを選び、展開する。実行ファイルはtunnel-client.exe。SHA256SUMS.txtとの照合もできる。将来はPlatform指定のサポート版を優先する。[6]

以下はPowerShell。展開先の実ファイルに合わせてパスを指定する。例のC:\Tools\OpenAITunnelは任意の保存先。

PowerShell
$TunnelExe = "C:\Tools\OpenAITunnel\tunnel-client.exe"
& $TunnelExe --version
& $TunnelExe help quickstart

2-4. uvがなければ導入する

PowerShell
winget install --id=astral-sh.uv -e

導入後はPowerShellを開き直し、uv --versionとuvx --versionを確認する。Pythonはuvxが必要に応じて用意する。UnityのGit URL導入にはGitもPATH上に必要。[3][7]

各Tunnelを起動するPowerShellでキーを読み込む

PowerShell
$key = Read-Host "OpenAI runtime API key" -AsSecureString
$env:CONTROL_PLANE_API_KEY = [System.Net.NetworkCredential]::new("", $key).Password
Remove-Variable key

この入力は本人がローカルで行う。キーをコマンド文字列に直接書かず、現在のPowerShellプロセスだけに渡す。Windowsの同じユーザーで動くプログラムからの隔離は別途必要。

3. Unityを接続する

3-1. Unityプロジェクトへパッケージを導入

バックアップしたプロジェクトをいつものUnityで開く。Window → Package Manager → ＋ → Add package from git URL…で以下を指定する。[3]

Package Manager · Git URL
https://github.com/CoplayDev/unity-mcp.git?path=/MCPForUnity#v10.2.0

Window → MCP for Unityを開き、HTTP Localを選ぶ。URLはhttp://127.0.0.1:8080。コンパイルが完了し、エラーがないことを確認する。既存のMCPが導入済みなら、別実装を重ねる前に現在の実装・版を確認する。

3-2. 同じ版のローカルMCPサーバーを起動

Unity用サーバーのPowerShellで実行する。すでに同じ8080番のサーバーが動いていれば二重起動しない。

PowerShell
$env:UNITY_MCP_DISABLE_TELEMETRY = "true"
uvx --from mcpforunityserver==10.2.0 mcp-for-unity `
  --transport http --http-host 127.0.0.1 --http-port 8080

そのPowerShellは開いたままにする。UnityのMCPウィンドウでConnectを押し、接続状態を確認する。UIからStart Serverした場合は、上の手動サーバーを追加起動しない。[3]

3-3. Unity用Tunnelを起動

別のPowerShellで2章の$TunnelExeとruntime keyを設定し、次を実行する。profileの作成は初回だけ。

PowerShell
$UnityTunnel = "TUNNEL_UNITY"
& $TunnelExe init --sample sample_mcp_remote_no_auth `
  --profile unity-local --tunnel-id $UnityTunnel `
  --mcp-server-url "http://127.0.0.1:8080/mcp"
& $TunnelExe doctor --profile unity-local --explain `
  --health.listen-addr "127.0.0.1:8081"
& $TunnelExe run --profile unity-local `
  --health.listen-addr "127.0.0.1:8081"

doctorで問題が出たらrunの前に直す。これは非公開loopbackサーバーなので追加のOAuthサーバーは作らない。OpenAIへの認証にはruntime keyとTunnel権限を使う。[1][2]

ローカル確認

PowerShell
Invoke-WebRequest "http://127.0.0.1:8081/healthz" -UseBasicParsing
Invoke-WebRequest "http://127.0.0.1:8081/readyz" -UseBasicParsing

別のPowerShellで確認する。両方HTTP 200を確認し、PCのブラウザーでhttp://127.0.0.1:8081/uiを開く。ここでhealthy/readyでも、まだクラウドからUnityの読み取りが成功した証拠にはならない。[2]

4. Blenderを接続する

4-1. アドオンを導入

Blenderの作業ファイルを保存する。PowerShellで以下を実行する。対応するアドオンを検出済みのBlenderフォルダーへコピーし、置換時は.bakを残す。[5]

PowerShell
$env:DISABLE_TELEMETRY = "true"
uvx mcp-for-blender@2.1.3 install-addon

BlenderのEdit → Preferences → Add-onsでInterface: MCP for Blenderを有効にする。3D ViewでN → MCP for Blenderを開く。現在のアドオンは自動起動が標準。停止していればConnect to MCP serverを押す。古い版の表示はStart MCP Server等の場合がある。[5]

localhost:9876で待ち受ける状態にする。ネットワーク公開、0.0.0.0への変更、ルーター転送はしない。アドオンのTCP通信には認証・暗号化がないため、loopbackを維持する。

4-2. Blender用Tunnelがstdioサーバーを起動

Blender用のPowerShellで2章の$TunnelExeとruntime keyを設定する。環境変数はtunnel-clientとそのMCP子プロセスに渡る。[2][5]

PowerShell
$env:DISABLE_TELEMETRY = "true"
$env:BLENDER_MCP_SAFE_MODE = "1"
$env:BLENDER_HOST = "localhost"
$env:BLENDER_PORT = "9876"
$BlenderTunnel = "TUNNEL_BLENDER"
$uvxPath = (Get-Command uvx.exe).Source.Replace("\", "/")
$BlenderCommand = '"' + $uvxPath + '" mcp-for-blender@2.1.3'
& $TunnelExe init --sample sample_mcp_stdio_local `
  --profile blender-local --tunnel-id $BlenderTunnel `
  --mcp-command $BlenderCommand
& $TunnelExe doctor --profile blender-local --explain `
  --health.listen-addr "127.0.0.1:8082"
& $TunnelExe run --profile blender-local `
  --health.listen-addr "127.0.0.1:8082"

stdio MCPサーバーはtunnel-clientが起動する。別のClaude/Codex等から同じBlender用サーバーを同時起動しない。BlenderとTunnelのPowerShellを開いたままにする。[5]

ローカル確認

PowerShell
Invoke-WebRequest "http://127.0.0.1:8082/healthz" -UseBasicParsing
Invoke-WebRequest "http://127.0.0.1:8082/readyz" -UseBasicParsing

PCのブラウザーでhttp://127.0.0.1:8082/uiを開く。stdioではreadyでもtools/listをまだ通していない場合があるため、5章のクラウド側チェックまで行う。[2]

Safe Modeはexecute_blender_codeへの検査で、完全なsandboxではない。通常の保存・読み込み・import/exportは許可され、直接TCPで送るexecute_codeは検査を通らない。重要ファイルは必ず別コピーにする。[5]

5. クラウド側へ登録し、実際に確認する

5-1. ChatGPTに2つの接続を登録

WebのChatGPTでSettings → Security and login → Developer modeを有効にする。ChatGPT Pluginsの＋から、Unity PCとBlender PCの2接続を作る。ConnectionはTunnelを選び、対応する実tunnel_idを選択または入力する。作成中は両方のtunnel-clientを稼働させる。[8]

ChatGPT Plugins
https://chatgpt.com/plugins

今回のローカルMCPは追加OAuthを実装していない構成。認証選択が表示されたらNo Authenticationを使うが、公開HTTPサーバーの無認証公開はしない。runtime keyはPCとOpenAIのTunnel制御用で、ChatGPTのMCP認証欄へ貼るものではない。[1][2][9]

5-2. 既存のUnity/Blenderスキルと結び付ける

接続の作成とツール発見が通った後、登録済み接続のURLからplugin_asdk_app…形式の技術IDを取得する。スキル入りpluginを作成・更新するときは、実際に登録したそのIDを接続先として使用する。packageの.app.jsonとmanifestの参照が正しい接続へ向いていることを確認する。[10]

GitHubにplugin packageがあること、スキルがインストール済みであること、Tunnelを作成したことは、それぞれ別段階。packageだけで認証・接続が完了した扱いにしない。必要なmappingが確認できるまで同じpackageを作り直し続けない。

5-3. 完了の判定

① 登録した各接続で実tools/listが取得できる
② Unityは現在のproject名・Unity版・開いているsceneを読み取れる
③ Blenderは現在のscene名・object一覧を読み取れる
④ dotの実際の会話から同じ接続のツールを呼び、PCの対象状態と一致する結果が返る
⑤ ここまで通ってから、バックアップした検証ファイルへ小さい編集を試す

検証依頼の例：
「Unity PCで今開いているプロジェクト名とシーン階層だけ読んで。変更・保存はしない」
「Blender PCで今のシーン名とオブジェクト一覧だけ読んで。変更・保存はしない」

ChatGPTで登録できても、このdotの会話へツールが出なければ、dotでの操作は未接続。その場合は接続設定・正しいapp binding・対象workspaceを確認し、使える状態になるまでPC操作の完了とはしない。

プラン・料金の扱い

Developer modeの公式技術資料はPro/Plusを含むread/write対応と記載する一方、Help Centerの一部はProをread/fetchのみと記載している。追加購入を先に行わず、実際の接続画面とツール利用可否を確認する。[9][11] Coplay版はMITの無料OSS。Tunnelのアカウント別課金条件・利用枠はPlatformの表示を確認し、APIモデルを別途使う場合はその利用料金も確認する。

6. 停止・復旧と一次資料

すぐ止める

まず各tunnel-clientのPowerShellでCtrl+C。BlenderのMCP接続も停止し、UnityのMCPウィンドウでDisconnect / Stop Serverを使う。不要になったらChatGPT側の接続を解除し、Platformでruntime keyを失効、Tunnelを削除する。開いた鍵入りPowerShellは閉じる。自動起動を設定した場合はそれも停止する。

詰まった箇所ごとの確認

・Tunnels access required：PlatformのorganizationとRead/Manage/Use権限を確認。ロール反映には最大30分の場合がある。[1]
・ChatGPTにTunnelが出ない：対象workspace関連付けとRead + Useを確認
・healthzは200、readyzは失敗：doctor --explainと/uiのLogsを確認
・readyでも道具一覧が出ない：実tools/listとMCP initialization、接続先・認証を確認
・Unity8080へつながらない：サーバー、Connect、Unityコンパイル、版10.2.0の組合せを確認
・Blender接続失敗：アドオン有効、GUI起動、9876、uvxの実パス、二重サーバーを確認
・8081/8082使用中：そのポートの所有プロセスを確認してから、healthポートを別のloopback空きポートへ変更。無関係なプロセスを止めない
・ツール変更後：接続のRefreshと新しい会話で確認。公開plugin更新とdeveloper-mode接続更新は別手順。[8]

本人が操作・承認する設定

runtime API keyの発行・入力、接続の有効化、ソフトウェア/アドオン導入、実際に許すプロジェクトと編集範囲の決定。こちらに代行させる場合は、PCアクセスと必要な設定変更を具体的に許可する。秘密入力は本人のローカル画面で行う。
