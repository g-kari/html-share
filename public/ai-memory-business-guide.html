AIの業務利用とメモリ

AIメモリと業務利用のリスク：ChatGPTとClaudeのメモリ機能を比較

確認日：2026年11月28日
一次資料はOpenAI公式ヘルプ（メモリ、Projects、一時チャット、データコントロール、保持、法人向けメモリFAQ）、Claude公式サポート（メモリと過去チャット検索、Projects、Incognitoチャット、学習利用）、OWASP GenAI Security ProjectのASI06です。製品の仕様は公式ページで確認できた範囲だけを書き、確認できなかった点は「未確認の点」に分けます。

要点
  1. 結論：許可された一般業務では、メモリは条件付きで有効化するのが基本です。案件ごとに参照範囲を分け、機密性が高い案件や契約で制限が必要な案件では無効化または利用制限を選びます。一律の無効化は安全側ですが、毎回のプロンプト作成、再説明、手戻りが増えるコストがあります。
  2. メモリが参照する情報は3層に分けて考えます。アカウント共通の指示（回答形式などの一般ルール）、プロジェクトの文脈（仕様、経緯、資料）、そのチャットの今回の依頼です。混同は主に2層目で起きます。
  3. 製品側の分離設定と、自然言語で「この案件の情報だけ使って」と頼むことは別物です。後者はアクセス制御の代替にはなりません。分離は設定（ChatGPTのプロジェクト専用メモリ、ClaudeのUse account memoryオフ）で担保します。
  4. 学習、保持、削除はメモリとは別の仕組みです。チャットを削除しても保存メモリは自動では消えません。逆に、メモリを切っても学習設定は変わりません。項目ごとに分けて確認が必要です。
  5. リスクは、他案件の情報、古い前提、過去の承認が混ざる「混同」と、汚染された情報がメモリに残って将来の回答を歪める「メモリポイズニング」です。対策は、定期点検と、架空データでの混在テストです。

メモリが参照する3つの層

「メモリをオンにするか」だけでは設計できません。回答に効いてくる情報は、出どころと効く範囲が違う3層に分かれます。第1層はアカウント共通の指示で、回答形式や一般的な進め方など、案件を問わないルールです。第2層はプロジェクトの文脈で、仕様、経緯、資料、過去の決定など、案件に閉じるべき情報です。第3層はそのチャットの今回の依頼で、会話が終われば効かなくてよい情報です。

業務利用で問題になるのは、主に第2層の扱いです。第2層が案件をまたいで参照されると、他案件の仕様や古い前提が混ざります。逆に第1層まで毎回チャットに書き直す運用にすると、無効化のコストがそのまま作業時間に乗ります。層ごとに「覚えさせるか」「どの範囲で参照させるか」を決めるのが、この記事の前提です。

ChatGPTのメモリ：保存メモリと履歴参照

ChatGPTのメモリには、性質の違う2つがあります。「保存したメモリ」は、利用者が明示的に覚えるよう頼んだ詳細や、ChatGPTが有用な文脈として保存した詳細で、チャット履歴とは別に保存されます。「チャット履歴を参照」は、過去の会話の関連情報を今後の応答に使う仕組みで、保存メモリとは別にオン・オフできます。ただし連動があり、「保存したメモリを参照」をオフにすると「チャット履歴を参照」もオフになります。

新しい形として、継続的に更新される広い概要（メモリの要約）を使う「改善されたメモリ」もあり、従来の項目リスト型の保存メモリと切り替えられます。改善されたメモリでは、プロジェクト専用メモリで文脈を特定プロジェクト内に限定できます（同じプロジェクト内のみ相互参照し、プロジェクト外とは相互に参照しません）。

プロジェクトのメモリ設定は、Enterprise／Edu向けの公式表で確認できます。プロジェクト内チャットでメモリが「default」の場合はChatGPTメモリを利用できますが、「project-only」の場合はChatGPTメモリは使えず、参照はプロジェクト内のみに限られます。どちらの場合も、カスタム指示は使えず、プロジェクト指示のみが適用されます。

設定場所は「設定 ＞ パーソナライズ ＞ メモリ」です。メモリをオフにしても過去のチャットは削除されません。再度オンにすると、履歴に残っているチャットから新たに情報を覚えることがあります。

Claudeのメモリ：トピック保存とプロジェクトメモリ

Claudeのメモリは、会話の終了後にまとめて要約するのではなく、チャット中に個別の「トピック」として随時保存されます。利用者が「これを覚えて」と指示して直接保存させることもできます。オン・オフは「Settings ＞ Your Claude」の「Generate memory from chats」で切り替え、覚えている内容は同じ画面の「Your memory」からトピックごとに確認、編集、削除できます。変更は以降の全会話に適用されます。

メモリとは別に「過去チャット検索」があります。有料プラン（Pro、Max、Ultra、Team、Enterprise）向けで、展開時点でデフォルト有効です。過去の会話を検索して参照し、参照時は元のチャットへのリンクが表示されます。「Search and reference chats」のトグルでオフにできます。

プロジェクトメモリはプロジェクトごとに独立しています。ただしデフォルトでは、プロジェクト内のチャットは「そのプロジェクトのメモリ」に加えて「プロジェクト外チャットのメモリ」も使います。他のプロジェクトのメモリは使いません。新しいメモリはそのプロジェクトに保存されますが、メモリがオンの間はプロジェクト外のチャットからも参照され得ます。完全に分離したい場合は、プロジェクトページのMemory欄で「Use account memory」をオフにします。これが、この記事の結論でいう「製品側の分離設定」の実例です。

1つのチャットだけメモリを切りたい場合は、新規チャット開始時に「+」メニューでMemoryをオフにします。そのチャットではメモリを使わず、保存もせず、過去チャット検索もしません。ただし履歴には残り、他の会話からの過去チャット検索では見つけられます。開始後に切り替えることはできず、変える場合は新しいチャットが必要です。センシティブな話題（健康、人種、宗教的信条、政治など）はデフォルトでは保存されず、保存するには専用設定のオプトインが必要です。

一時的な会話：一時チャットとIncognito

どちらの製品にも、メモリに残さない一時的な会話の仕組みがあります。ChatGPTの一時チャットは、保存しない限り履歴に表示されず、その会話の間はメモリを作成・更新せず、モデル改善にも使われません。開始前に「パーソナライズあり」を選んだ場合だけ、既存のメモリを使って回答します。保存すると通常のチャットに変換され、通常の保持とモデル改善設定が適用されます。安全上の目的で、コピーが最長30日間保持される場合があります。

ClaudeのIncognitoチャットは、チャット履歴にもメモリにも保存されず、過去チャット検索でも引き出されません。プロジェクト内では使えません（プロジェクト内では、1チャットだけメモリをオフにする方法が代替として案内されています）。閉じたIncognitoチャットは再び開けず、通常チャットへの変換もできません。プロフィール情報（カスタムスタイルや個人の好み）にはアクセスできる点は、一時チャットでパーソナライズありを選んだ場合と似ています。

使い分けの目安は単純です。履歴にも残したくない一時的な相談はIncognito（Claude）か一時チャット（ChatGPT）。履歴は残してよいが、メモリに混ぜたくない作業は、Claudeならメモリ・オフで開始したチャットが該当します。

学習・保持・削除はメモリとは別

メモリ、学習、保持、削除は、それぞれ別の設定と別の動きをします。OpenAIのデータコントロールのページは、メモリはパーソナライズを制御するもので、モデルトレーニングの設定とは別だと明記しています。メモリをオフにしても学習設定は変わらず、学習をオフにしてもメモリは消えません。

学習の既定値はプランで分かれます。ChatGPTの個人向け（Free、Plus、Pro）では「すべての人のためにモデルを改善する」がデフォルトで有効で、チャットや記憶した情報がモデル改善に使われることがあります。Business、Enterprise、Edu、ヘルスケア向けのワークスペースでは、デフォルトでは学習に使われません。Claudeでは、商用製品（Claude for Work、Anthropic APIなど）はデフォルトで入力・出力を学習に使いません。ただし、利用者がフィードバック（サムズアップ／ダウンなど）を送った場合は例外で、その会話全体が最大5年間保存され、学習に使われることがあります。

保持と削除で実務上いちばん重要なのは、ChatGPTで「チャットを削除しても、そこから別途保存されたメモリは自動では消えない」点です。完全に消すには、保存済みメモリの項目を削除し、その情報に言及したチャットを削除し、ライブラリやSpaceのファイル、接続済みアプリ側に情報があればそちらからも削除する必要があります。削除の反映にも段階があり、チャットは表示からは即時に消えますが、システムからの完全削除は30日以内が目安です。「チャット履歴を参照」をオフにした場合も、過去のチャットから覚えた情報は30日以内に削除される予定です。削除された保存メモリのログが、安全性とデバッグの目的で最長30日間保持される場合もあります。

通常チャットの保持は、ChatGPTでは利用者が削除するか、ワークスペースの保持ポリシーで削除されるまで続きます。Claudeのメモリは、既存のチャットデータ保持ポリシーに従って保持されると公式ページにあります（具体的な日数は公式ページに記載がありませんでした）。

法人・組織での管理

法人利用では、個人設定の上に組織の管理が乗ります。ChatGPT Businessでは、メモリは各個人のアカウントに紐づき、同じワークスペースの他メンバーとは共有されません。メモリとパーソナライズの制御は個人とワークスペースの両方にあり、ワークスペースの所有者が全体でオフにすると、そのワークスペースの既存の保存メモリは削除されます。Businessのデータ（会話とメモリを含む）は、デフォルトではモデル学習に使われません。

ClaudeのTeam／Enterpriseでは、組織のOwnerがメモリの利用可否を管理します。組織全体の設定はデフォルトでオンで、その間は個人が自分の設定を管理します。Ownerが組織でメモリをオフにすると、全ユーザーで利用と保存が止まり、個人は再びオンにできません。Ownerでも個人のメモリを閲覧・編集はできません。組織の作成時期によって初期状態が違い、2026年10月31日（太平洋時間）以降に作成された組織では各メンバーのメモリは初期オン、それより古い組織では各メンバーがオンにするまでオフです。HIPAA有効組織など一部の組織では初期オンになりません。

管理者にとっての確認点は3つです。組織の既定値（オンかオフか）、個人が変えられる範囲、オフにしたときに既存メモリがどうなるか（削除されるのか、使えなくなるだけか）。この3点は製品ごとに答えが違うため、導入時に公式ページで確認して社内ルールに書き写しておくのが安全です。

リスク：混同とメモリポイズニング

1つ目のリスクは混同です。他案件の情報、古い前提、過去に承認された内容が、別の案件の回答に混ざります。原因は、分離されていない第2層（プロジェクトの文脈）が案件をまたいで参照されることです。症状は「前の案件の仕様で答える」「終了したはずの前提で計画する」「過去の承認を現在の承認と取り違える」などで、回答自体は自然な文章で出てくるため、気づきにくいのが特徴です。

2つ目はメモリポイズニングです。OWASP GenAI Security ProjectのASI06（Memory & Context Poisoning）は、汚染された情報がメモリや検索用の保存領域に入り、将来の推論、計画、ツールの使い方を歪めるリスクを扱います。入り口は、アップロード、APIフィード、利用者の入力、エージェント同士のやり取りなどです。一度保存されると汚染はセッションをまたいで残り、目標の解釈やツールの選択にまで影響し得ます。対策として挙げられているのは、メモリへの書き込み前の内容検証、メモリの分離（セグメンテーション）、保持の最小化、出所の記録と異常な更新の検知、未検証メモリの失効、スナップショットとロールバック、高リスク操作への人間のレビューです。

どちらのリスクも、「この案件の話だけ使って」と自然言語で頼むことでは防げません。それはモデルへのお願いであり、アクセス制御ではありません。防ぐのは、製品側の分離設定、メモリに何が入っているかの点検、そして混入を検知するテストです。

運用：定期点検と混在テスト

有効化したメモリは、置きっぱなしにせず運用します。点検は3点です。第1に、メモリの中身の棚卸しです。ChatGPTなら保存済みメモリ（またはメモリの要約）、ClaudeならYour memoryのトピック一覧を開き、古い前提、終了した案件、誤って入った他案件の情報がないかを確認して、編集または削除します。第2に、参照範囲の確認です。案件が増えた、担当が変わった、契約条件が変わったタイミングで、プロジェクトの分離設定（プロジェクト専用メモリ、Use account memory）が意図どおりかを見直します。第3に、混在テストです。

混在テストは、架空の2案件を使って行います。案件Aと案件Bに、それぞれ固有の架空の数値や名称（実データは使わない）を覚えさせ、AのチャットでBの前提が混ざらないか、BのチャットでAの数値が出てこないかを確認します。分離設定を変えたとき、プランや製品の仕様が変わったときにも同じテストを繰り返します。結果は「混ざった／混ざらなかった」と、混ざった場合はどの設定で起きたかを記録します。

効率を測る：3条件の比較枠組み

「メモリでどれだけ速くなるか」には、製品共通の公式な測定値がありません。導入判断には、自組織の作業で測る必要があります。測り方は、同じ種類の作業を次の3条件で比べる枠組みです。数値は実測するもので、この記事では作りません（未測定の効率値は掲載しません）。

条件設定何が分かるか
A：無効＋指示なしメモリ無効。毎回、文脈をプロンプトに書く基準線。安全だが再説明のコストが最大
B：無効＋固定指示メモリ無効。第1層（共通の指示）だけを固定文として毎回渡す固定指示で代替できる範囲と、残る再説明の量
C：有効・分離＋指示ありメモリ有効。案件単位に分離し、固定指示も併用メモリ自体の効果と、混同の発生有無

測る指標は4つです。プロンプト作成時間（作業開始から送信まで）、修正回数（意図と違う前提を直した回数）、品質（出来上がりの評価を同じ物差しで）、混在件数（他案件の情報や古い前提が混ざった件数）。条件Cで時間が短くても、混在件数が増えるなら分離設定の見直しが先です。逆に条件Bで条件Cとほぼ同じ結果なら、その作業ではメモリを使わない選択が合理的です。

用語補足

保存メモリ（Saved memories）
ChatGPTで、利用者が明示的に覚えるよう頼んだ詳細や、ChatGPTが有用な文脈として保存した詳細。チャット履歴とは別に保存され、元のチャットを削除しても自動では消えません。
プロジェクトメモリ
プロジェクト単位で保持されるメモリの総称。ChatGPTのプロジェクト専用メモリ、Claudeのプロジェクトごとのメモリが該当します。案件単位の分離はこの単位で行います。
メモリポイズニング（Memory poisoning）
汚染された情報がAIのメモリや検索用の保存領域に入り込み、将来の回答、計画、ツールの使い方を歪める攻撃・現象。OWASP GenAI Security ProjectのASI06で扱われます。
