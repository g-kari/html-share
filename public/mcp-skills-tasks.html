Skills over MCPとTasks：MCP 2周年でサーバーが手順と長時間の仕事を持てるようになった

確認日：2026年11月25日
一次資料はAnthropicの公式記事（Claude公式サイト、2026-11-24公開）、MCP公式ドキュメントのSkills／Tasks拡張ページ、各拡張の仕様、Claude Code公式ドキュメントです。発端となったClaudeDevsのX投稿は出典に挙げますが、内容の根拠は公式資料で確認しました。

要点
  1. MCPの2周年発表は4つの更新の組み合わせです。Skills over MCPはパブリックベータ、TasksとElicitation（処理の途中での入力要求）は正式提供（GA）、File Uploadsは提供開始が近日と、段階がそれぞれ違います。まとめて「全部正式提供」とは読めません。
  2. Skills over MCPでは、MCPサーバーがツールと一緒にスキル（手順書）を公開できます。ツール名と説明は「何ができるか」までしか伝えませんが、スキルは進め方そのものを渡します。Claudeはスキルを必要な時だけ読み込み、スキルはサーバーの更新に追従するので、利用者側に別のインストールは要りません。
  3. Tasksでは、サーバーがツール呼び出しへの最終結果の代わりにタスク（タスクIDと状態）を返せます。Claudeは完了を待たずに別の作業を進め、状態を確認しながら結果を後から受け取ります。対象は長時間の処理や、エージェントループごと任せる仕事です。
  4. どちらも開かれたMCP仕様と拡張の上の機能です。対応したサーバーはClaude以外の互換クライアントでも動くと公式記事は書いています。ただし、プランごとの提供範囲と未確認の日程が残ります（本文の「未確認の点」節）。

発表の全体像：4つの更新と段階の違い

2026年11月24日、Anthropicは公式記事「MCP servers can now ship skills, run tasks, and more with Claude」を公開しました。MCP（Model Context Protocol）は、AIエージェントをデータのあるシステムへつなぐ標準として2年前に公開されたものです。公式記事は、今回の更新で「Claudeはサーバーと、もう1人のエージェントと働くように付き合えるようになる」とまとめています。学ぶ（スキル）、任せる（Tasks）、途中で入力をもらう（Elicitation）、ファイルをやり取りする（File Uploads）の4方向です。

段階はそろっていません。Skills over MCPはパブリックベータ、TasksとElicitationは正式提供、File Uploadsは「近日提供開始（rolling out soon）」です。記事やニュースで読むときは、この段階の違いが実質の差になります。

土台の数字も公式記事に出ています。MCPのSDKは月間7億超のダウンロードがあり、Claude向けのMCPコネクタは10,000を超えます。今回の機能は、この規模のサーバー群に対して「対応すれば互換クライアントでも動く」形で仕様側に入っています。

Skills over MCP：サーバーが手順を届ける

従来のMCPサーバーが届ける中心はツールでした。ツール名と説明は、サーバーに何ができるかは伝えますが、特定の仕事をどう進めるかまでは伝わりません。手順は利用者側がプロンプトで補うか、ローカルにスキルを用意して別途インストールする必要がありました。

Skills over MCPでは、サーバーがツールと一緒にスキルを公開します。スキルは、ベストプラクティス、手順の流れ、利用者のアカウントや組織に合わせた進め方（プレイブック）をまとめたものです。中身の形式はAgent Skillsの仕様に従い、中心は SKILL.md というファイルで、補助ファイルを持てます。

公式記事が挙げる利用例は、Shopify（販売者のオンラインストアの設計と更新を一貫して行う）、HubSpot（顧客のオンボーディングと初期設定）、Atlassian（組織の文脈を使った分析）、Carta（アップロードされた文書から株式発行の下書きと発行。こちらは近日対応）です。いずれも「ツールを呼べる」だけでは足りず、手順と組織固有の進め方が要る仕事です。

ポイントは2つあります。1つは、Claudeがスキルを必要な時だけ読み込むため、常駐する文脈の量が増えにくいことです。もう1つは、スキルがサーバーと一緒に更新されることです。提供側はツールと手順を1か所で直せて、利用者側に配布やインストールの手順が増えません。

スキルの動き：発見、検証、必要な時だけ読み込み

仕様側の姿は、MCP公式ドキュメントのSkills拡張ページと、拡張仕様（SEP-2640、Final）で確認できます。拡張の識別子は io.modelcontextprotocol/skills です。新しい転送を発明するのではなく、既存のResources（リソース）の仕組みの上に載っています。

サーバーは、スキルの各ファイルをリソースとして公開します。URIは慣例として skill:// スキームを使います。クライアントは skills/list でサーバーが提供するスキルを列挙し、skills/get でURIを指定して1件を取り直せます。一覧に出ないスキルでも、サーバーは skills/get に応答しなければなりません。ファイルの中身自体は resources/read で読みます。

読み込みには検証と承認が挟まります。各スキルの一覧エントリにはファイルの一覧（マニフェスト）が付き、各ファイルのSHA-256ダイジェストとバイト数が載ります。ホストは、使う前に各ファイルのサイズとダイジェストを照合し、SKILL.md のフロントマター（name と description が必須）がエントリと一致するかを確認します。ファイルが追加・変更・削除されれば、前に得た承認は失効し、取り直しと再承認が必要です。

「必要な時だけ」の側も仕様の要件です。ホストは、接続時や一覧取得の時点でファイルを先読みしてはいけません。スキルの内容は信頼できない入力として扱い、コード実行やツール許可のような権限はスキルごとに利用者の明示承認が要る、と仕様は定めています。サーバーが配る手順書は便利な一方で、配布元がモデルの振る舞いを変える入口にもなるため、この検証と承認の層が仕様に組み込まれています。

Skills over MCPの提供範囲と制約

提供範囲は公式記事とClaude Code公式ドキュメントの両方に記載があります。対象はClaudeとClaude Codeです。Pro、Max、Ultraの各プランでは既定で有効です。Teamプランでは管理者が有効化すると使えます。Enterpriseは「近日（coming soon）」で、具体的な日付は公式に示されていません。

Claude Codeでは、スキル名は <サーバー名>:<スキル名> の形になり、プロンプトで / を打つと候補から探せます。読み込み時の承認は権限ルールで調整でき、サーバー単位・スキル単位で「毎回聞く」「拒否する」「許可する」を設定できます。一部のコネクタのスキルにはAnthropicのセキュリティスキャンが入り、スキャンを通った版だけが読み込まれます。

制約も公式ドキュメントに明記されています。1サーバーあたり表示されるスキルは最大100件です。スキャン対象のスキルには、テキストファイル1件あたり100KB、スキル全体で400KBの上限があります。対応しない環境もあります。たとえばClaude CodeのクラウドセッションやAgent SDK等は対象外とされ、VS Code拡張では段階的に展開中です。使う環境が対象かどうかは、公式ドキュメントの「Where MCP skills are supported」を確認する必要があります。

Tasks：呼び出しと結果の受け取りを分ける

従来のツール呼び出しは、処理が終わるまでClaudeが次へ進めませんでした。数分で終わる処理なら待てますが、CIの調査、バッチ処理、人の承認待ちのような仕事では、接続を持ったまま待つ形が持ちません。

Tasksはこの待ち方を変えます。サーバーは、ツール呼び出しへの応答として最終結果の代わりにタスクを返せます。タスクにはサーバーが発行したタスクIDと現在の状態が入り、処理はサーバー側で続きます。Claudeはその間、別の作業を進められます。状態が完了になれば、最終結果は元の呼び出しが同期で返したはずの結果と同じ形で受け取ります。

公式記事の利用例はZoomInfoで、以前は複数のプロンプトに分けていた深いアカウント・連絡先の調査をTasksで回しています。公式記事は「時間がかかる処理や、エージェントループそのもの」をサーバーが引き受けられると書いています。

提供段階は正式提供（GA）です。対象はClaudeとClaude Codeで、Pro、Max、Ultraの各プランで使え、TeamとEnterpriseの組織へは展開中とされています。Elicitationも同じ段階で正式提供になりました。こちらは、課金やデータ削除のような確認が要る操作で、サーバーが処理を止めて利用者へフォームやリンクで問い合わせ、答えを受けて続きから再開する仕組みです。

Tasksの状態と仕様

仕様側は、MCP公式ドキュメントのTasks拡張ページと拡張仕様で確認できます。拡張の識別子は io.modelcontextprotocol/tasks です。タスク化はサーバー主導で、クライアントがリクエストごとに拡張への対応を宣言し、その範囲でサーバーがリクエストごとにタスクにするかどうかを決めます。現行仕様でタスク化できるのは tools/call のみです。

メソッドは3つです。tasks/get は状態の確認（ポーリング）で、終端状態では最終結果やエラーもここに載ります。tasks/update は、タスクが入力待ち（input_required）のときに、サーバーから来た要求への答えを返すために使います。tasks/cancel は取り消しの意思を伝えますが、協調的で、サーバーが必ず止める義務はありません。

状態は5つです。working（処理中）、input_required（入力待ち）、completed（完了。結果は result）、failed（失敗。JSON-RPCエラーは error）、cancelled（取り消し済み）。後ろの3つは終端で、到達後は状態が変わりません。タスクには有効期間（TTL）と推奨ポーリング間隔も付き、クライアントはタスクIDを保存しておけば、切断や再起動の後でも同じIDで続きを確認できます。状態の通知（notifications/tasks）もありますが任意で、既定はポーリングです。

なお、Claude Codeの実装では tasks/result や tasks/list は使われず、結果は tasks/get の応答に載せる形だと公式ドキュメントに書かれています。仕様にある全メソッドが、そのまま各クライアントで使われるわけではありません。

組み合わせで何が変わるか

2つの機能は、サーバーの役割の違う側面を広げます。Skills over MCPは「知識の渡し方」、Tasksは「仕事の渡し方」です。従来のMCPサーバーは、呼ばれるたびに応答する道具の集合でした。スキルを受け取ればClaudeはそのサービスの流儀で道具を使え、タスクを渡せば長時間の仕事をサーバー側の実行に任せられます。

ElicitationとFile Uploadsを合わせると、公式記事の総括どおりの形になります。サーバーから学び（スキル）、サーバーへ任せ（Tasks）、途中で人に聞き（Elicitation）、ファイルを受け渡す（File Uploads）。サーバーが「もう1人のエージェント」に近い相手になる、というのが今回の発表の中心です。

実務での効きどころは、手順が固まっているのに長い仕事です。組織の進め方をスキルで固定し、実行の待ち時間をTasksで外へ逃がすと、プロンプトで手順を毎回説明し直す必要も、完了まで接続を抱える必要も減ります。反対に、短い呼び出しだけで終わるサーバーでは、Tasksの出番はほぼありません。スキルの側も、手順が単純なサーバーではツール説明で足ります。

未確認の点

公式資料で確認できなかった点は、次のとおりです。この記事では、公式が「近日」「展開中」と書いた範囲を超えて書いていません。

  • Skills over MCPのEnterprise提供の具体的な日付（公式記事は「近日」のみ）。
  • File Uploadsの提供開始日と、最初に対応するサーバーの範囲（公式記事は「近日提供開始」のみ。Cartaのスキルも同じく近日とされます）。
  • TasksとElicitationのTeam・Enterprise組織への展開が完了する時期（公式記事は「展開中」のみ）。
  • Skills over MCPのパブリックベータが終わり、正式提供へ移る時期。
  • Claude以外の互換クライアントについて、SkillsとTasksへの対応状況の全体像。公式ドキュメントは対応マトリクスへの案内を出していますが、本記事では個別クライアントの対応可否までは確認していません。

もう1点、段階の読み違いに注意が要ります。今回の発表では、TasksとElicitationが正式提供で、Skills over MCPはベータです。ベータの間は、対応するコネクタが一部に限られる場合があるとClaude Codeの公式ドキュメントも書いています。「サーバーがスキルを出しているのにClaude Codeで見えない」という場合は、ベータ側の制限の可能性があります。
