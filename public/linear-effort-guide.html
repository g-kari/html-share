Linearで工数管理できる？
見積もりと実績時間を分けて考える

作業の大きさを見積もり、進み具合を追うならLinearが使えます。実際に何時間かかったかも知りたい場合は、時間記録を別に用意するのが実用的です。

作業量と進捗を知りたい

標準のEstimate・Project・Cycleから始める。

実働時間を集計したい

時間記録サービスとの連携、または別の記録表を使う。

標準機能での作業量の見積もり

Linearでは一つひとつの作業をIssueとして管理します。EstimateはそのIssueの複雑さや大きさを表す見積もりです。チームごとに有効にし、1・2・3・5・8のような数値や、XS・S・M・L・XLのようなサイズを使います。

EstimateはProjectやCycleの進捗集計に使われます。Projectは複数のIssueをまとめる単位、Cycleは一定期間の作業をまとめる単位です。Estimateの「3」を入力しても、自動的に「3時間」を記録したことにはなりません。

出典：Linear Docs：Estimates

「Effort」と「Time」の意味と注意点

Effort
Estimateの合計。実働時間の合計ではありません。
Cycle Time
Issueの開始から完了までの経過時間。
Lead Time
Issueの作成から完了までの経過時間。

たとえば、月曜日に着手して水曜日に完了した作業でも、手を動かした時間は合計2時間かもしれません。経過時間をそのまま人時や請求時間として扱うと、確認待ちや中断を実作業に数えてしまいます。

出典：Linear Docs：Insightsの集計指標

未見積もりのIssueは、初期設定では1ポイントとして数えられます。明示的な0ポイントとは別です。集計前にチームの見積もり設定を確認すると、合計値の読み違いを減らせます。

外部の時間記録との組み合わせ

今回確認した公式ドキュメントでは、実働時間を記録する標準タイマーや、実績時間専用のタイムシートは確認できませんでした。一方、Linearの公式連携一覧には、時間記録サービスが掲載されています。

連携先できること導入前の確認
Everhourブラウザ拡張でLinear内に時間記録の操作を追加。ProjectやIssueの情報をレポートに利用。ブラウザ中心の使い方に合うか。料金・最低利用人数・同期範囲を確認。
HarvestIssueからタイマーを開始・停止し、Issueへのリンク付きでHarvestの時間記録を作成。対応ブラウザと拡張機能、既存の時間記録・請求運用との相性を確認。

Linearの利用料とは別に、連携先の契約や料金がかかる場合があります。連携時に共有されるIssue名やProject名、アクセス権も確認してください。

少量なら別の表で手入力してもよい

個人の振り返りが目的なら、日付・Issueへのリンク・作業内容・実績分数を表に記録する方法もあります。Linearには見積もりと進捗を置き、時間は表で集計します。これは運用例で、Linearに専用の時間記録機能を追加するものではありません。

説明欄やコメントに時間を書き残すこともできますが、自由文は集計や訂正が難しくなります。請求や複数人の集計に使うなら、記録形式をそろえられる時間管理サービスのほうが扱いやすいでしょう。

個人開発での2週間の運用例

個人開発ではまず2週間だけ試す運用を提案します。最初から細かい管理を作り込まず、「今週どの程度進められたか」と「何に時間を使ったか」を分けて振り返ります。

  1. 作業を完了判定できる単位に分ける「サイトを改善する」より「検索結果の空表示を直す」のように、終わりがわかるIssueにします。
  2. 着手前にEstimateを付ける小・中・大など、自分の中で比較できる目安を決めます。ポイントの基準を途中で変えたら、その変更も残します。
  3. 必要な作業だけ、時間を別記録する開始・終了時刻、または実績分数を残します。調査、実装、確認のどこに時間を使ったかも一言添えます。
  4. 週末に見積もりと実績を振り返る予定より大きかった作業や、待ち時間が長かった作業を確認。次のIssue分割や見積もりに反映します。
記録の例。架空の作業であり、ポイントと時間の対応表ではありません。
作業見積もり実績時間振り返り
文言の修正1 pt20分想定どおり
検索の不具合修正3 pt120分再現条件の調査が長かった
一覧表示の調整2 pt95分スマートフォンの確認を追加

「1ポイント＝何時間」と固定するより、似た作業の実績を見積もりの参考にするほうが始めやすい運用です。チームごとに見積もりの尺度が異なるため、ポイント数だけで人やチームの生産性を比較する使い方も避けるのが無難です。

API・MCPによる入力と振り返りの補助

LinearはGraphQL APIとWebhookを公開しています。MCPは対応するAIツールからIssue・Project・コメントなどを検索・作成・更新するための接続方法です。

たとえば、AIに作業をIssueへ分割してもらう、完了したIssueを集めて週次の振り返りを作る、といった使い方が考えられます。APIと外部の時間記録を組み合わせれば、Issueごとの見積もりと実績を並べる仕組みも作れます。ただし、集計処理や連携の実装は別途必要です。

APIやMCPへの接続だけで、実働時間を自動計測できるわけではありません。利用するツールが扱える項目と、時間記録の保存先を確認してください。

出典：API and Webhooks、MCP server

二つの目的に合わせた使い分け

作業量と進捗はLinearで管理し、実際に使った時間も必要なら、時間記録サービスや表を組み合わせます。個人開発なら、この分担から小さく始めるのがよさそうです。
