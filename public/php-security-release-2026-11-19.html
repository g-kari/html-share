Critical（7件）

CVE-2026-129474：マジックメソッドのバックトレース収集時の use-after-free

GHSA-8mjj-2r7p-4hg2 ｜ CVSS 4.0: 9.2 ｜ 影響：PHP 8.5 のみ

__call() や __callStatic() に入る際のバックトレースで引数を集めるときに、解放済みメモリを参照します。未認証の攻撃者が、細工したリクエストで致命的エラーを起こしながらマジックメソッドへ入らせることで、PHP ワーカーの権限で任意のコードを実行できる可能性があります。発動条件は fatal_error_backtraces=1（PHP 8.5 では既定で有効）と zend.exception_ignore_args=0 の両方です。php.ini-production は zend.exception_ignore_args=1 を設定するため、その設定を使っている環境では実証された攻撃経路は成立しません。

CVE-2026-129496：タイムゾーンキャッシュの use-after-free

GHSA-gr4f-wgx5-jpfv ｜ CVSS 4.0: 9.2 ｜ 影響：全ブランチ

プロセス起動中に PHP のファイルベースの error_log へ診断が書かれると、タイムゾーンキャッシュへの参照が残ったまま起動用メモリが解放され、後続リクエストの初期化の早い段階で別の診断が発生すると解放済みキャッシュへ触れます。リモートからメモリ破壊、ワーカークラッシュ、コード実行に至る可能性があります。条件は、起動時にファイルベースの error_log へ診断が出ること（例：date.timezone の不正値、セッション設定の警告）、非スレッドセーフビルドであること、リクエスト初期化の早い段階で別の診断（max_input_vars 超過の警告など）が出ることです。PHP-FPM 自身のエラーログへの出力だけでは条件を満たしません。

CVE-2026-129289：PHP-FPM のリクエストスマグリング

GHSA-qc49-hpvq-g2w6 ｜ CVSS 4.0: 9.2 ｜ 影響：全ブランチ（PHP-FPM／LSAPI）

アプリケーションが php://input を開いただけで本文を最後まで読まない場合、未読のボディが破棄されず、持続接続上に残ります。細工した multipart ボディと組み合わせると、未認証の攻撃者が残ったバイト列を別の FastCGI リクエストとして解釈させ、フロント側のルーティングや認証を回避して PHP コードを実行できます。FCGI_KEEP_CONN が有効な PHP-FPM で成立します。本文を読む前にストリームを作るフレームワークでは、対象エンドポイントがボディを使わない場合でも成立し得ます。

CVE-2026-115560：セッションシリアライザの不一致による逆シリアル化

GHSA-658j-r8rw-q6mx ｜ CVSS 4.0: 9.2 ｜ 影響：全ブランチ

セッションのアップロードプログレスが書き込んだデータを、別のシリアライザで読み取ると、セッションキーの一部がシリアル化されたオブジェクトデータとして解釈されます。読み取り側のアプリケーションに適切なガジェットチェーンがあると、PHP ワーカーの権限でコード実行に至ります。条件は、アップロードプログレスが有効で攻撃者が multipart アップロードを送れること、書き込み側が php_binary または php_serialize、読み取り側が php シリアライザで、同一セッション ID・同一保存先を共有することです。アプリケーションが session_start() の前に session.serialize_handler を php へ変える構成や、設定の異なる複数のアプリ・プール・仮想ホストが同じセッション保存先を使う構成で起こります。

CVE-2026-126714：セッションファイルの部分上書きによる逆シリアル化

GHSA-fm2m-fjf5-v3cp ｜ CVSS 4.0: 9.2 ｜ 影響：全ブランチ

既定の files セッションハンドラは、更新時に既存ファイルへ新しい内容を書き込みますが、書き込みが途中で止まると、新旧2つのセッションが混ざったファイルが残ります。攻撃者がセッション内容を操作でき、置き換え書き込みを中断させられると、次にセッションを開いたときに攻撃者制御のオブジェクトが逆シリアル化され、ガジェットチェーンがあればコード実行に至ります。

CVE-2026-129481：セッション終了が中断された後の use-after-free

GHSA-g3vh-838c-65v7 ｜ CVSS 4.0: 9.2 ｜ 影響：PHP 8.3 以降

セッション終了処理が、ユーザ定義ストリームラッパの stream_close() などコールバック内の致命的エラーで中断されると、スクリプトファイル名へのポインタが解放済みメモリを指したまま残り、同じワーカーで処理される次のリクエストで use-after-free が起きます。10月に公開された CVE-2026-109619 に対する修正が不完全だったものの続報です。条件は、セッション内にストリームリソースを保持し、そのクローズ処理で致命的エラーが発生することです。次のリクエストは別のユーザやセッションのものでも構いません。

CVE-2026-129182：終了処理後の致命的エラーバックトレース再投入による use-after-free

GHSA-2fjv-p558-g82m ｜ CVSS 4.0: 9.2 ｜ 影響：PHP 8.5 のみ

CVE-2026-109619 の修正（PHP 8.5.12）で終了処理時にクリアされるようになった致命的エラーのバックトレースが、その後の終了処理で発生した別の致命的診断によって再び設定され、解放済みメモリへの参照が次のリクエストへ残ります。具体例として、max_memory_limit が全体設定とパス別設定の両方にある構成での INI 復元失敗や、zlib.output_compression と output_handler の競合による設定エラーが挙げられています。発動には、同じワーカーで処理される後続リクエストの、実行エンジン初期化前の診断も必要です。PHP-FPM と mod_php の両方が対象です。

High（4件）

CVE-2026-129291：PHP-FPM の epoll use-after-free（ローカル権限昇格）

GHSA-jm4m-qfqx-967m ｜ CVSS 4.0: 8.8 ｜ 影響：PHP 8.2.7 以降の全ブランチ

catch_workers_output が有効な PHP-FPM で、ワーカー終了時の出力パイプ処理の競合により、解放済みのワーカーレコードへの epoll イベントが配送されます。権限のない FPM ワーカーで PHP コードを実行できる攻撃者がこれを悪用すると、FPM マスターの権限（多くの場合 root）でコマンドを実行できます。リモート単独では発動せず、ワーカー内でのコード実行が前提です。

CVE-2026-127960：折り返し HTTP 応答ヘッダによる DoS

GHSA-mmf9-xm3v-hg2x ｜ CVSS 4.0: 8.7 ｜ 影響：PHP 8.2.28／8.3.18／8.4.5 以降と 8.5

PHP の HTTP ストリームラッパが、継続行で折り返された応答ヘッダを処理する際に、行ごとに全体をコピーし直すため、多数の短い継続行を含む応答で CPU を大量に消費します。悪意あるサーバーの応答を file_get_contents() などで取得するアプリケーションが対象です。攻撃者自身が応答を制御できるか、アプリケーションが取得するサーバーへ影響できることが前提です。

CVE-2026-128064：HTTPS／FTPS スキームの大文字混在で平文送信

GHSA-f6gg-rchx-xw8j ｜ CVSS 4.0: 8.2 ｜ 影響：全ブランチ

URL スキームの S が大文字の場合（例：HTTPS://、httpS://、FTPS://）、ストリームラッパが TLS を有効にせず平文で送信します。パスワード、認証トークン、POST ボディ、転送ファイルがネットワーク上の観測者に漏れます。リダイレクト先の URL でも起こり、正規の HTTPS 接続から大文字スキームの URL へ 307 リダイレクトされると、保持された POST ボディや認証ヘッダが平文で送られます。アプリケーションが大文字小文字を区別しない検証を通した URL を使う場合に発動します。

CVE-2026-128090：PHAR の OpenSSL 署名のダウングレードによる検証バイパス

GHSA-68fq-fh7h-f8gr ｜ CVSS 4.0: 7.7 ｜ 影響：全ブランチ

OpenSSL で署名された Phar アーカイブの署名種別を、SHA-256 のような鍵なしハッシュへ書き換えると、公開鍵による検証を経ずに任意の内容のアーカイブが受け入れられます。phar.require_hash=1 でも防げません。前提は、攻撃者が Phar ファイル自体を改変できることです（信頼する公開鍵ファイルは改変しません）。改変したアーカイブを実行するアプリケーションで、攻撃者制御の PHP コードが動きます。

Medium（6件）

CVE-2026-129538：php-cgi の PATH_INFO 補正での境界外読み書き

GHSA-5j3f-64r7-f564 ｜ CVSS 4.0: 6.9 ｜ 影響：全ブランチ（php-cgi のみ）

php-cgi が、サーバーから渡されたスクリプトパスと PATH_INFO の不整合により、バッファの外を読み書きします。プロセスのクラッシュ、メモリ露出、メモリ破壊の可能性があります。条件は cgi.fix_pathinfo=1（既定）と、特定の Web サーバーのマッピングです。PHP-FPM と Apache モジュール版は対象外です。

CVE-2026-129506：SOAP の DTD 実体参照処理での use-after-free

GHSA-4646-p932-gw34 ｜ CVSS 4.0: 6.3 ｜ 影響：全ブランチ

SOAP 拡張が、DTD と属性値内の実体参照を含む XML を処理する際に解放済みメモリを読みます。攻撃者制御の SOAP XML を処理する公開エンドポイントで、PHP プロセスをクラッシュさせられます。攻撃者が制御する WSDL やスキーマを読み込むアプリケーションも対象です。

CVE-2026-129438：RFC 3986 URI の文字列化の不具合

GHSA-mg3p-mxj9-g2mm ｜ CVSS 4.0: 6.3 ｜ 影響：PHP 8.5 のみ

PHP 8.5 で導入された Uri\Rfc3986\Uri が、約 2 GiB 級の巨大な URI を文字列化する際に、切り捨てられた、または無効な文字列を正常な結果として返します。メモリ枯渇やプロセス終了も起こり得ます。従来の parse_url() と Uri\WhatWg\Url は対象外です。

CVE-2026-129501：DOM の XML シリアライズでの二重解放

GHSA-x8r7-mg3g-74hg ｜ CVSS 4.0: 6.3 ｜ 影響：PHP 8.4 以降

新しい DOM 実装の XML シリアライザが、生成した名前空間プレフィックスの所有権を要素と子孫で共有してしまい、同じメモリを複数回解放します。攻撃者が制御する XML や HTML に対して saveXml() を呼ぶアプリケーションで、プロセスがクラッシュします。不正な形式の入力でなくても成立します。

CVE-2026-15353：SOAP の配列次元の不具合による情報漏えい

GHSA-q23r-hr55-xmpg ｜ CVSS 4.0: 6.3 ｜ 影響：全ブランチ

SOAP 拡張が、不正な arraySize を持つエンコード済み配列を処理する際に未初期化のヒープメモリ（4バイト）を読み、その値を配列キーとして使います。アプリケーションがデコード後の配列を応答などに含める場合に、その値が攻撃者へ漏れます。受け付けるだけでは漏えいは成立しません。

CVE-2026-129292：PHP-FPM ステータスページの XSS

GHSA-3mg3-cr28-46gc ｜ CVSS 4.0: 5.3 ｜ 影響：全ブランチ

PHP-FPM のフルステータス応答で、リクエストメソッド、認証ユーザ、スクリプトファイル名がエスケープされずに含まれます。未認証の攻撃者が通常のリクエストでスコアボードに HTML や JavaScript を仕込み、運用者が後でフル HTML ステータスページを開くと実行されます。攻撃者はステータスエンドポイント自体へアクセスできなくても仕込めます。

パッチ提供状況

公式のソース tarball と Windows バイナリは、2026年11月19日の公開と同時に php.net から提供が始まっています。

ディストリビューションのパッケージは、本記事の確認時点（公開から約1時間後、日本時間 23時台）では、Debian セキュリティトラッカーと Ubuntu の CVE ページに今回の CVE の登録を確認できませんでした。Debian、Ubuntu、RHEL、Alpine などを使う環境は、各ディストリビューションのセキュリティ告知とパッケージ更新を確認してください。公式ビルドを使う環境は、php.net の修正版へそのまま更新できます。

更新できない場合の緩和策

恒久対策は修正版への更新です。更新までの間は、該当する構成で次が効きます。

  • CVE-2026-129474（8.5）：zend.exception_ignore_args=1 を設定すると、実証された攻撃経路は成立しません。php.ini-production の既定値です。fatal_error_backtraces=0 でも回避できます。
  • CVE-2026-115560：使っていないなら session.upload_progress.enabled=0 でアップロードプログレスを無効化します。あわせて、同一セッション保存先を使う環境間で session.serialize_handler が混在していないかを確認します。
  • CVE-2026-129289：php://input を開くフレームワークやアプリケーションでは、リクエストボディを最後まで消費する実装になっているかを確認します。FCGI_KEEP_CONN の有効化範囲も見直してください。
  • CVE-2026-129292：PHP-FPM のステータスエンドポイントを外部へ公開しないでください。
  • CVE-2026-129291：catch_workers_output が不要なら無効化します。
  • CVE-2026-128090：Phar ファイルを外部から書き換え可能な場所に置かないでください。署名のダウングレードは phar.require_hash では防げません。
