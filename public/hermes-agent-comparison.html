まず結論：何を作りたいかで選ぶ

「自分の好みや仕事の手順を覚える、道具付きの個人AI」を育てたいなら、Hermes Agent は有力な候補。一方、決まった自動処理や独自アプリの開発では、別の土台が使いやすいこともあります。

自分用の相棒を育てたいHermes Agent：記憶・再利用できる手順・会話窓口をまとめて試す チャットや端末の接続を組みたいOpenClaw：多様な窓口と、交換可能な実行部を中心に構成する 記憶を持つ独自AIアプリを作りたいLetta：SDK で独自の画面や複数ユーザーの仕組みを作る 毎日の処理を図で組みたいn8n：条件分岐・サービス連携・承認を見える形にする

主目的が「コードを書き、テストして直す」なら Claude Code も比較対象です。これらはすべて同じ種類の製品ではありません。上の選び分けは、機能の公式説明をもとにした用途別の判断で、性能ランキングではありません。

根拠：Hermes 概要、OpenClaw 概要、Letta SDK、n8n Agents、Claude Code 概要

AIモデルと、エージェントは別の部品

モデルは文章を読んで次の行動を考える「頭脳」。エージェントは、その頭脳に記憶・道具・繰り返しの実行を組み合わせる「仕事の仕組み」です。Hermes Agent は後者にあたります。

Hermes を入れたら、専用の超大型モデルが必須？
必須ではありません。Nous Portal、OpenRouter、OpenAI などの接続先や、自前の対応エンドポイントを選べます。ただし、道具を正しく呼べるか・長い文脈を扱えるかはモデル次第です。

根拠：公式 README、Tools & Toolsets、Local Models

「使うほど育つ」は、何が変わるのか

中心は、仕事で得た知識を文章として保存し、次の仕事で再利用する仕組みです。この説明でいう「学習」は、記憶や手順書の更新です。通常利用で基盤モデルの重みを毎回再訓練する、という意味ではありません。

記憶は、短い重要メモ

標準の MEMORY.md は環境や学んだ事柄、USER.md はユーザーの好みを保存。既定の上限はそれぞれ 2,200 文字と 1,375 文字で、会話開始時に読み込みます。会話履歴は別の SQLite データベースに保存して検索できます。

Persistent Memory

技能は、必要なときの手順書

スキルは文章・参考資料・スクリプトなどをまとめた再利用用の束。関連する仕事で読み込み、作成や更新もできます。「/learn」で資料や経験を技能にする入口もあります。

Hermes Agent

個人の相棒技能の再利用

向く：同じ人の依頼を繰り返し受け、調査・ファイル作成・開発補助などを横断するAI。最初から記憶、技能、道具、会話窓口を一緒に試せます。

気にする点：モデルの道具呼び出し精度、記憶の訂正、常時稼働の維持、実行権限。個人の全データを最初から渡す構成は避けるのが実験しやすい進め方です。

概要、記憶、技能

OpenClaw

接続を組み立てる個人AIの直接比較

向く：チャットや端末の多様な入口、交換可能なモデル・実行部、プラグインを中心に、自分の個人AI基盤を組む用途。Hermes に最も近い比較対象です。

気にする点：Markdown メモや検索、技能も備えます。違いは「記憶があるか」より、運用の仕方と構成の相性で判断します。サンドボックスは既定で無効なので、有効化の確認が重要です。

概要、記憶、隔離の既定、ライセンス・データ送信

Letta

独自アプリ継続する記憶

向く：記憶を持つAIを、自作のWeb画面やアプリに組み込む用途。SDK では一度作ったエージェントを継続し、モデルや動く端末を変えながら扱えます。

気にする点：現行の MemFS は Git 管理の記憶で、標準では意味検索の索引を持ちません。ローカルと自己ホストの選択肢もあります。現行対話CLIの既定は unrestricted なので、初期テストでは承認が必要なモードを明示する判断が重要です。

SDK、MemFS、自己運用、権限の既定

n8n

図で自動化条件と承認

向く：「毎朝取得→要約→保存」「条件に合ったら下書き→人が確認」のように、順番や分岐が明確な処理。AIを必要な部分だけに置く構成に向いています。

気にする点：新しい Agents 機能は Preview。セッション記憶や任意の episodic memory、ツール、スケジュールもあります。現行の episodic memory には OpenAI 接続が必要です。自己ホストには一部追加設定や制約があります。Community 版は利用条件付きで、MIT のように無条件の再販・ホスト提供ができるソフトではありません。

概要、Agents と Preview 制約、道具の承認、ライセンスFAQ

Claude Code

コードの編集・検証開発を先に進める

向く：自作AIのアプリや連携コードを作る、既存コードのバグを直す、テストする、といった開発作業。自分用AIの「実装を手伝う道具」として組み合わせる考え方もあります。

気にする点：自動記憶や指示ファイルもあり、記憶のない使い捨てチャットではありません。権限とOSレベルの隔離を組み合わせます。個人プランと商用契約では、学習利用やデータ保持の扱いを別に確認します。

概要、記憶、権限、データの扱い

安全性は、保存先と実行権限を分けて考える

自己ホストでも、外部AIへ送る内容は外へ出ます。記憶ファイルを自分のPCに置くことと、推論に使うデータを外部へ送らないことは別です。クラウドの検索・ブラウザー・記憶サービスを足せば、その接続先も確認対象になります。

用意されている防御

Hermes は利用者制限、DMペアリング、危険コマンドの確認、ファイル書き込み制限、コンテナー隔離、文脈ファイルの検査などを備えます。

Security

設定次第で変わる境界

既定の local 実行はホスト上で動き、隔離はありません。Docker 等の隔離バックエンドでは、通常の危険コマンド確認が省略される仕様です。

実行先の既定、バックエンド別の境界

コンテナーだけで、外部操作は無害になりません。
中に渡したAPIキーや共有ファイル、サービス側で許可した権限には影響できます。公式資料も、コンテナーへ渡した環境変数の秘密情報は読み出し・外部送信されうると注意しています。コマンド承認は、送信・購入・アカウント変更などすべてを判断する万能な承認機構ではありません。

根拠：隔離と環境変数の注意。外部操作の影響に関する説明は、この境界からの安全設計上の判断です。

  • 権限は小さく：最初は公開情報の調査と、試験用フォルダーだけ
  • 読み取りと書き込みを分ける：送信・削除・公開・支払いは別の承認地点を作る
  • 第三者の技能も確認：文章だけでなく同梱スクリプト・接続先・必要権限を見る
  • 障害に備える：記憶・技能・設定・会話をバックアップし、戻せるか試す

上の4点は本レポートの運用提案です。製品の防御機能を実際に侵入テストした結果ではありません。プロンプト注入の検査や危険パターン検知には限界があります。

関連資料：文脈ファイル検査の限界、技能の配布・検査、ローカルモデル

最初は、小さな「覚えて作る」実験から

最初からメール・全ファイル・決済までつなぐと、失敗の原因も権限の影響も追いづらくなります。次の実験なら、記憶・技能・道具の価値を切り分けて確認できます。

  1. 試験用の環境とデータを決める公開資料、ダミーのプロジェクトメモ、作業用フォルダーを用意。重要な本番データは入れない。
  2. モデルと道具を最小限つなぐ公式インストールガイドを確認し、モデル1つと必要な読み取り道具から開始。API側にも試験予算の上限を設ける。
  3. 同じテーマで、1つ作らせる例：「公開記事3本を比較し、日本語の短いHTMLにまとめる」。出典、ファイル内容、実行ログを人が確認する。
  4. 好みと手順を保存して確認する「私の好み」と「次回の手順」を分けて保存。実ファイルが更新されたか、誤った推測が混ざっていないかを見る。
  5. 新しい会話で、似た仕事を頼む説明し直す量が減ったか、根拠が残ったか、料金が増えすぎないかを比較。うまくいってから常時稼働や連携を増やす。

これは本レポートが提案する検証手順です。実機への導入・課金・外部連携を実行した記録ではありません。

用語を、普通の言葉に戻す

項目を開くと、意味とこの比較での読み方がわかります。

エージェント

頼まれた目的に向けて、次に何をするか考え、道具を使い、結果を見て進める仕組み。文章を返すだけでなく、実行のループを持ちます。

LLM / AIモデル

文章などから応答や判断を生成する部分。エージェントの「頭脳」です。同じ本体でもモデルを替えると、能力・速度・費用が変わります。

ツール / ツール呼び出し

検索、ファイル操作、コマンド、APIなどの実行機能。モデルが適切な名前や引数で呼べる必要があり、返答が上手でも実行が得意とは限りません。

スキル / 技能

特定の仕事で使う手順書・参考資料・必要なスクリプトをまとめたもの。単なる説明文だけとは限らず、配布元と同梱コードを確認します。

メモリー / 永続記憶

会話を閉じても残る情報。常に読む短い要点、必要なときだけ検索する履歴、技能などで役割が違います。保存は、正しさの保証ではありません。

コンテキスト / 文脈

その時点でモデルに渡されている情報。会話・指示・記憶・道具の結果などが入ります。保存されていても、いま読まれているとは限りません。

API / プロバイダー / BYOK

APIはサービスをプログラムから使う窓口、プロバイダーは提供者。BYOK は「自分のAPIキーを持ち込む」方式です。費用やデータ条件は接続先でも確認します。

MCP

AIアプリが外部の道具やデータ源に接続するための共通の方式。接続方法が共通でも、接続先の安全性・権限・料金が同じになるわけではありません。

CLI / TUI / SDK

CLIはコマンドで操作する入口、TUIは端末内の画面、SDKは自作アプリから機能を使うための開発部品です。まず使うならApp/CLI、組み込むならSDKを見ます。

gateway / cron / webhook

gatewayはチャットとAIなどをつなぐ常駐の入口。cronは時刻や周期での実行。webhookは「出来事が起きた」という外部通知です。正確な役割は製品ごとに異なります。

自己ホスト / ローカルモデル / VPS

自己ホストは自分で実行環境を管理すること。ローカルモデルは自分の機器で推論すること。VPSは借りた仮想サーバーです。自己ホストに外部モデルを組み合わせることもできます。

サンドボックス / プロンプト注入

サンドボックスは実行の影響を限定する環境。プロンプト注入は、Webページや資料などがAIに不正な指示を混ぜる攻撃です。隔離・権限・承認・確認を重ねて対処します。

トークン / 従量課金 / execution

トークンはモデルが扱う文章などの単位で、文字数とは一致しません。従量課金は使った量での料金。n8n の execution は処理の1回分で、単純な「ノード数」とは別です。

MIT / ソース公開 / Preview

MIT は再利用しやすいライセンスですが、モデルや外部サービスの契約は別。ソースが読める製品でも利用条件に制限がある場合があります。Preview は試験提供中で、仕様や制約が変わりやすい段階です。
