T3 Codeとは：Claude CodeやCodexを1つの画面で操る無料のオープンソース。T3 Chatとは別物

確認日：2026年11月24日（2026年11月25日にテレメトリの裏取りで「データの扱い」を訂正）
一次資料：T3 Code公式サイト／GitHubリポジトリ（README）／公式FAQ。公式で確認できない箇所は、本文と出典に明記します。

要点
  1. T3 Codeは、T3 Chatとは別の製品です。T3 Chatが各社のAIモデルと文章で会話する汎用チャットなのに対し、T3 Codeは、Claude CodeやCodexなどのコーディングエージェントを自分のマシンで動かし、デスクトップ・Web・スマホから操作するための画面です。運営はどちらも米国のT3 Tools, Inc.です。
  2. T3 Code自身はAIモデルでもエージェントでもありません。公式FAQは「ハーネス（エージェントの実行基盤）ではなく、それらを使う側」と明言しています。動かすのは、利用者がすでに入れてログイン済みのエージェントで、契約と課金は各提供元のままです。
  3. 料金は無料です。公式FAQには「私たちに払う方法自体がない」と書かれています。ソースコードはMITライセンスで公開されています。T3 Chatの月額プランを買う必要はありません。
  4. T3 Chatとの接点は1つだけあります。リモート接続の仕組みT3 Connectでつなげるマシンの上限が、無料では3台のところ、T3 Chatの有料プランを連携するとProで10台、Premierで100台に増えます（公式FAQ）。
  5. エージェントの実行場所は自分のマシンや自分のVPSで、コードがT3のサーバへ送られることはないと公式FAQが明記しています。机で始めた作業の続きを、スマホから承認だけして進める、という使い方が前面に出ています。
  6. 利用状況データ（テレメトリ）は、コードとは別に、既定でT3自前のサーバへ送られます。2026年11月24日までは、他のツールのログイン情報ファイルから読んだアカウント識別子のハッシュも含まれていました（同日の修正で削除）。詳細は「データの扱い」に書きました。
  7. GitHubリポジトリの作成は2026年2月で、公式サイトの表示ではスターは7万5千を超えています。一方で公式READMEは「非常に初期のプロジェクトで、バグを想定してください」と明記しています。

T3 Chatとの違い

結論から言うと、名前と運営は同じでも、用途も形態も料金の仕組みも違う別製品です。T3 Chatはブラウザで開くチャットサービスで、モデルはT3側が用意し、利用者は月額プランと利用量メーターの範囲で各社のモデルと会話します。T3 Codeは自分のマシンにインストールするオープンソースのアプリで、モデル利用は利用者自身の契約（Claude CodeやCodexのサブスクリプションなど）をそのまま使います。

項目T3 ChatT3 Code
用途汎用AIチャット（文章の質問と回答）コーディングエージェントの操作（コードの読み書きと実行）
形態ブラウザで使うクラウドサービス自分のマシンに入れるアプリ＋小さなサーバ
対象ユーザーモデルを使い分けたい一般の利用者複数のコーディングエージェントを使う開発者
モデルの用意T3側が用意し、利用量はメーター制利用者の契約とログインをそのまま使う
料金Free／Pro 月8ドル／Premier 月50ドル無料（払う方法がない）。エージェントの契約料は別
実行場所T3側の基盤から各社のモデルへ自分のマシンや自分のVPS
公開形態サービスとして提供オープンソース（MITライセンス）

共通点は運営（T3 Tools）と、「複数のAIを1つの画面に集める」という発想です。接点は料金の節で述べるT3 Connectの上限だけで、T3 Chatのプランに入っていなくてもT3 Codeは使えます。T3 Chat側の詳しい内容はT3 Chatの記事にまとめています。なお、同じく複数のコーディングエージェントを扱う別の選択肢にOrcaがあり、管理の単位（スレッドかワークツリーか）などの違いをOrcaの記事で比べています。

T3 Codeとは：仕組み

T3 Code（t3.codes）は、公式サイトの言葉では「コーディングエージェントのための、オープンソースのコントロールプレーン（制御面）」です。GitHubのREADMEは「エージェントハーネスのコントロールサーフェス（操作面）」と表現しています。どちらも、T3 Code自身がエージェントとして働くのではなく、エージェントを動かして見せる側だという意味です。

この区別は公式FAQが丁寧に説明しています。モデルに道具の実行や結果の受け渡しを担わせる実行基盤を「ハーネス」と呼び、Claude CodeやCodexがそれに当たります。T3 Codeはハーネスではなく、それらを使う側で、ハーネスなしでは動きません。FAQの比喩では、LLMがシェフ、ハーネスがキッチン、T3 Codeは「好きなキッチンを持ち込めるレストラン」です。

仕組みは、操作画面と実行場所の分離です。自分のマシンで小さなサーバが動き、インストール済みのエージェント（ハーネス）を起動します。デスクトップアプリ、Webアプリ（app.t3.codes）、iOS・Androidのスマホアプリはすべて同じサーバにつながり、同じスレッド（作業の単位）を表示します。机の前のPCで始めた作業を、外出先のスマホで確認して次のステップを承認する、という流れが想定されています。

運営はT3 Tools, Inc.で、商標ポリシーとライセンス表記に社名が明記されています。GitHubの組織は pingdotgg で、リポジトリの作成は2026年2月8日です。2026年3月にはCodex向けのWeb UIとして紹介され始め（二次資料）、その後対応エージェントとクライアントを広げました。バージョンは0.1.x系で更新が頻繁です。

対応するコーディングエージェント

README（確認時点）では、Claude Code、Codex、Cursor、OpenCode、Grok Build、Antigravity、Kiro、Pi、Muse Code、fxに対応し、さらにACP（Agent Client Protocol）に対応する任意のエージェントも接続できるとしています。前提は、各エージェントの公式CLIがそのマシンに入っていて、ログインが済んでいることです。

契約（サブスクリプション）ではなくAPIキーで使う形も選べます。公式FAQによると、設定から別のプロバイダを追加して、独自のキーやエンドポイントを指定でき、Claude向けにはOpenRouterを使う手順も用意されています。一方、ローカルで動くモデルには対応しません。これはFAQが理由つきで明言している方針です。

主な機能

中心は「スレッド」という作業単位の管理です。スレッドごとに担当エージェントやモデルを決め、作業の途中でも別のモデルやエージェントに切り替えて引き継げます（例：Claudeに途中まで任せて、続きをCodexへ渡す）。

  • 並行作業：スレッドごとにGitのワークツリーとブランチを分けられるため、複数のエージェントが同じリポジトリで別々の作業を同時に進められます。
  • diffの確認：ターンごとに何が変わったかを確認してから次へ進められます。
  • PRまで1ボタン：コミット、プッシュ、プルリクエストの作成を1つのボタンで行います。PRの題と本文は自動生成され、既存のGitHub認証を使います（公式サイト）。
  • 権限モード：コマンド実行などの承認範囲を切り替える仕組みが、公式ドキュメントに用意されています。
  • 音声入力：スマホやデスクトップで、音声から指示を入力できます（公式FAQ）。
  • 外部からの接続：外のエージェントがMCP経由でT3 Codeを呼び出す接続も、公式ドキュメントにあります。

リモート利用

エージェントは、T3 Codeサーバを動かしているマシンで実行されます。そのマシンは自宅のデスクトップでも、サーバやVPSでも構いません。マシンに t3 up でサーバを常駐させておけば、スマホアプリやブラウザ（app.t3.codes）から同じスレッドを操作できます。スマホはあくまでリモコンで、作業するマシンの電源は入れたままにしておく必要があります（公式FAQ）。

接続の方法は3つあります。自前で用意されたT3 Connect（Cloudflareのトンネルを使い、接続の取り次ぎだけを行います）、同じネットワーク内での直接接続、Tailscale経由です。公式FAQは、T3 Connectが不安定な場合の代替としてTailscaleも案内しています。

料金とT3 Chatプランとの関係

T3 Codeの利用料は無料です。公式FAQの「How much does T3 Code cost?」への答えは「Nothing. There's no way to pay us to use T3 Code.（何も。T3 Codeの利用料を私たちに払う方法自体がありません）」で、ソースコードはMITライセンスのオープンソースです。払う必要があるのは、Claude CodeやCodexなど、自分が使うエージェントの契約料だけで、それはT3 Codeを使う前と同じです。T3側がトークンを再販することもありません。

アカウントとプランの関係は次のとおりです。T3 Code自体の利用に、T3 Chatの契約は要りません。ただしリモート接続のT3 Connectにはアカウント単位の上限があり、無料ではエージェントを動かすマシンを3台まで接続できます。この上限は、T3 Chatの有料プランを連携すると増えます。Proの連携で10台、Premierの連携で100台です。無料プランのT3 Chatを連携しても上限は3台のままです（いずれも公式FAQ）。数えるのはマシンの台数で、接続するスマホやブラウザは数えません。

なお公式FAQは、T3 Connectの無料提供について「請求額が受け入れがたくなれば方針を変えるかもしれない」とも書いています。上限を避けたい場合は、ソースコードのフォークや自前ホスト、Tailscaleで代替できると案内されています。

データの扱い

コードとプロンプトは、自分のマシンからモデルの提供元（AnthropicやOpenAIなど）へ直接送られ、T3のサーバへは送られません。T3 Connectを使う場合も、通信は自分のマシン上のCloudflareトンネルを通り、T3側のリレーは接続を取り次ぐだけで、HTTPやWebSocketのセッションを中継しません（公式FAQ）。ただし、これはコードとプロンプトの話です。利用状況データの送信は別にあります。

利用状況データ（テレメトリ）は、既定でT3へ送られます。内容は、使う提供元やモデル、権限モード、ターンの結果、所要時間、トークン数などで、プロンプトや応答、ファイルの中身、認証トークンは含まれないと公式文書にあります。送信先はT3自前のサーバ（ingest.t3.codes）で、受け取ったイベントは、コピーが自社に残ってから分析サービスのPostHogへ転送されます（2026年10月のPR #15028。それまではPostHogへ直接送られていました）。

この送信は、2026年3月6日のPR #174で入りました。既定はオンで、止める方法は環境変数だけでした。利用者からの指摘（Issue #1397、2026年3月）によれば、その環境変数はREADMEにもドキュメントにもUIにも書かれていませんでした。公式サイトのトップには「No telemetry（テレメトリなし）」「Unless you opt in. Full stop.（オプトインしない限り。以上）」と書かれていた時期がありますが、この2行は2026年6月18日のホームページ改修（PR #3137）で削除されています。改修の説明に、テレメトリへの言及はありません。

識別子の扱いも広がっていました。導入当初から、サーバはCodexのログイン情報ファイル（~/.codex/auth.json）にあるアカウントIDを読み、ハッシュ化して送信に使っていました。2026年10月19日のPR #21506では、同じファイルのIDトークンからOpenAIのユーザーIDを取り出し、Claude Codeのファイル（~/.claude.json）のアカウントUUIDも読むようになりました。どちらも無塩のSHA-256でハッシュ化され、インストールの「所有者」としてイベントに付けられました。この提供元アカウント識別子の読み取りは、告発を受けた2026年11月24日のPR #42299で削除されました。現在のコードが読むのは、T3 Connectのアカウントと、接続してくるデバイスの識別子（いずれもハッシュ化）です。

診断用の送信もあります。T3 Connectの接続トレースはAxiomへ送られます。告発時点の公式文書（2026年11月23日版）には、ブラウザ版にはトレースを止めるスイッチがなく、モバイル版も環境変数や管理ポリシーでは止められないと書かれていました。公式文書はその後更新され、現在の版ではモバイル版の設定スイッチが案内されています。

設定画面へのオフスイッチの要望への対応も、リポジトリで確認できます。要望のIssue #1397は「対応予定なし（not planned）」で閉じられ、メンテナは「オプトアウトを簡単にはしない。利用者数を把握することが重要だ」という趣旨のコメントを残しています。スイッチを追加するコミュニティのPR（#13458、#16763、#21248、#27077）も、いずれも取り込まれずに閉じられました。

止める方法は次のとおりです。サーバを起動する前に環境変数 T3CODE_TELEMETRY_ENABLED=false（または DO_NOT_TRACK=1）を設定すると、利用状況データと、サーバからのトレース送信が止まります。トレースだけは T3CODE_OTEL_SDK_DISABLED=true でも止まります（公式文書）。

導入の流れ

前提は、少なくとも1つのエージェントが、そのマシンでインストールとログインを済ませていることです。そのうえでT3 Codeを入れます。コマンドライン版は curl -fsSL https://t3.codes/install.sh | sh（WindowsはPowerShell向けのスクリプト）で t3 コマンドが入ります。インストールせずに試す場合は npx t3@latest です。デスクトップアプリは公式サイトからダウンロードできるほか、macOSは brew install --cask t3-code、Windowsは winget install T3Tools.T3Code などで入れられます。

t3 を実行するとサーバが起動し、Webアプリが開きます。常駐させたい場合は t3 service install、更新は t3 update です。対応OSはWindows、macOS、Linuxですが、Intel Mac向けの t3 バイナリはないため、Intel Macではデスクトップアプリを使います。WindowsではWSLの中でエージェントを動かすこともできます（公式FAQ）。

注意点と未確認事項

  • 初期段階のプロジェクトです。公式READMEは「We are very very early in this project. Expect bugs.（非常に初期のプロジェクトです。バグを想定してください）」と明記し、外部からの貢献も基本的に受け付けていません（小さな修正は検討される場合があります）。重要な作業の本命にするかは、この前提で判断してください。
  • ローカルモデルには対応しません。公式FAQが方針として明言しています。手元のモデルだけで完結させたい用途には向きません。
  • エージェントの利用上限は各提供元の契約のままです。たとえばClaudeの5時間枠の消費については、FAQが版ごとの挙動に触れています（v0.1.7以降はClaude Code直接利用と同じ割合と説明）。枠の管理はT3 Codeではなく提供元側で行われます。
  • MITライセンスが及ぶのはソースコードだけです。T3 Codeの名前やロゴはT3 Toolsの商標で、フォークを公開する場合は自前のブランドに替える必要があります（READMEの商標の節）。
  • 日本語の画面表示の提供状況は、この記事では確認していません。ドキュメントは英語が正本です。
  • この記事では、外部の校正ツール（yomiyasu）は実行していません。数値と出典は原稿作成時に一次資料と照合しています。
  • テレメトリの記述は、2026年11月24日の告発を受けて、2026年11月25日に公開リポジトリのPRとコード、公式文書で裏取りし、訂正しました。裏取りの範囲では、告発の6項目はいずれも裏付けが取れています。確認できていないのは、スイッチ追加のPR4件をそれぞれ誰が閉じたかの内訳です。
