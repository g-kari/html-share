WHY IT MATTERS

何がエクスプロイトにつながるの？

アプリのログイン画面だけでは守り切れない、PHP内部のメモリ・リクエスト状態管理の問題です。影響はWeb workerの権限での未認証のコード実行。単なる「アップロードファイルの拡張子チェック漏れ」ではありません。以下は原因の概念図で、攻撃用データや手順ではありません。

CVE-2026-109618 · OOM

作りかけの状態が残る

入力処理等でメモリ不足OOM = Out Of Memory
↓
初期化途中の処理を中断内部データが不完全なまま
↓
後片付けが正しいデータだと思う不正なメモリ参照からコード実行へ

mod_phpはリクエスト開始に失敗しても後片付けを行うため、アプリの認証・入力チェックが動く前に成立する実証があります。FPMは開始失敗時にchildを終了するため同じ経路は残りませんが、正常開始後のアプリ処理でOOMになる場合は別に影響し得ます。

部分緩和：109618

memory_limit=-1 と、入口側の制限

管理者が上書きされない形でPHPのメモリ制限を外すと、攻撃者が予測できるPHP内のOOMを減らせます。ただし実メモリの割当失敗は残り、無制限化はメモリ枯渇・サービス停止の危険も増やします。単独で真似する「安全設定」ではありません。全workerを再起動し、pool・directory・applicationの別設定で有限値に戻っていないことも確認します。

公式は小さなpost_max_sizeと、プロキシ等での展開後サイズ・入力数・multipart構造の制限も案内。cgroup等の上限は可用性の境界であり、完全防御ではありません。RLIMIT_AS / RLIMIT_DATAへの置換は、脆弱な割当失敗を起こすため不可と明記されています。

「対象外の古いOS」はどうなる？

PHP本家のサポートと、OS・配布元のサポートは別の時計です。さらにOSが保守中でも、使っているPHPストリームや外部リポジトリが終了済みの場合があります。

PHP本家の保守対象

8.2 / 8.3 / 8.4 / 8.5

セキュリティ保守は順に2026 / 2027 / 2028 / 2029年の12月31日まで。今回の修正版は8.2.35 / 8.3.36 / 8.4.27 / 8.5.12です。8.2は年末の保守終了にも備えてください。

Windowsの古いOSも「動く」と「保守中」を分ける
  • Windows 8.1：Microsoftの延長サポートは2023年1月10日に終了。PHPの最低動作要件を満たしても、OS保守中とはなりません。Microsoft公式FAQ
  • Windows Server 2012 / 2012 R2：通常の延長サポートは2023年10月10日に終了。ESUの3年目も2026年10月13日までと公式表に記載。ESU契約があっただけで今後も保守され続けるとは扱いません。Microsoft公式ESU表
  • Windows 10：通常保守は2025年10月14日に終了。現時点の個人向けESU公式ページは、対象22H2の登録済み端末に2027年10月12日までの限定セキュリティ更新を案内しています。企業用・LTSCは別条件。どれも別途入れたPHPの修正を保証する制度ではありません。Microsoft公式個人向けESU

これらはOS自体の保守情報です。PHPの修正版告知はOS保守の延長ではありません。Windows向けの実際の配布物と、稼働PHPへの適用を別に確認します。

古い環境で今夜の修正版を入れられないなら：対応OS・PHPへの移行を準備する、既に契約中の保守が今回を扱うか確認する、修正まで公開経路を絞る、といった選択を分けます。「古い版だから対象外で安全」ではありません。

A SAFE CHECKLIST

自分の環境を確認する順番

  1. 導入元を知る：OS公式、外部リポジトリ、Homebrew、Dockerイメージ、ホスティング管理画面、製品同梱のどれか。
  2. 全部の実体を把握：Web用PHP-FPM / Apache、CLI、ジョブ、別コンテナは同じ版・設定とは限りません。
  3. 公式のCVE別修正版と照合：PHP表示の短い版だけでなく、完全なパッケージ番号、対象リポジトリ・ストリーム・OS・CPUを確認。
  4. 適用後を別確認：ファイル更新、稼働プロセスの切替、通常のログイン・アップロード等の動作確認を分け、反映して初めて対応完了とします。
管理者向け：読み取り確認の例と注意

php -vとphp --iniはCLIの情報です。これだけでWeb側も安全とは確認できません。パッケージ管理情報で完全な版と導入元を調べ、Web用プロセス・管理画面・デプロイ記録と照合してください。

公開phpinfoページの新設、攻撃文字列やPoCの送信、外部サイトへの脆弱性スキャンは不要です。この調査では行っていません。
