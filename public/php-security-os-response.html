23時は「全OSの更新完了時刻」ではない

PHP公式は2026年10月21日 23:00 JST（14:00 UTC）に、重大な脆弱性2件の緊急更新を予定しています。影響版・修正版・技術詳細は、そのリリースと同時公開予定。この時点では番号を推測しません。

PHP公式の予告。CVE-2026-109618 / CVE-2026-109619は香港GovCERTの公式警告で照合。PHP2Shellはここでは通称として扱います。

  1. 01PHP本家が修正影響版と修正版を発表
  2. 02配布元が組み込むUbuntu、RHEL、Homebrew等が配布
  3. 03管理者が適用正しい環境・導入元を更新
  4. 04稼働中まで確認古いプロセスやコンテナが残っていないか
大事：設定変更だけで「完全に安全」とは言えません。
確認できた暫定策は一部経路を閉じるもの。各OSの修正版、実際の適用、稼働中の確認を分けて見ます。

PHPはサーバー側で動く言語・実行環境です。GoやTLS証明書の問題と同じものではありません。このPHPの告知だけから「Goも更新が必要」とは判断しません。

WHY IT MATTERS

何がエクスプロイトにつながるの？

なぜ緊急なのか：PHP公式は2件ともCVSS v4.0 9.2 / Criticalと予告しています。ただし、認証の要否、対象機能、各OS・SAPI、正確な攻撃成立条件は公式詳細の公開待ちです。「PHPを使う全サイトで必ず侵入できる」とは断定できません。

1. 外から届く入力リクエストやデータを受ける
↓
2. PHP内部の不具合どの処理・条件かは公開待ち
↓
3. 本来許されない処理の恐れ影響は公式詳細を確認して更新

これは危険のつながりを説明する概念図で、今回の攻撃手順・実証ではありません。原因が公開されたら「原因 → 届く入力 → 必要な構成・権限 → 影響」に分けて置き換えます。

一部の経路については先行した公式情報あり：CloudLinuxは、multipartアップロードのセッション進捗処理を狙う既知形状に対するWAFルールを公開しました。ただし同社自身が問題はその経路だけではないと説明しています。

A SAFE CHECKLIST

自分の環境を確認する順番

  1. 導入元を知る：OS公式、外部リポジトリ、Homebrew、Dockerイメージ、ホスティング管理画面、製品同梱のどれか。
  2. 全部の実体を把握：Web用PHP-FPM / Apache、CLI、ジョブ、別コンテナは同じ版・設定とは限りません。
  3. 公式のCVE別修正版と照合：PHP表示の短い版だけでなく、完全なパッケージ番号、対象リポジトリ・ストリーム・OS・CPUを確認。
  4. 適用後を別確認：ファイル更新、稼働プロセスの切替、通常のログイン・アップロード等の動作確認を分け、反映して初めて対応完了とします。
管理者向け：読み取り確認の例と注意

php -vとphp --iniはCLIの情報です。これだけでWeb側も安全とは確認できません。パッケージ管理情報で完全な版と導入元を調べ、Web用プロセス・管理画面・デプロイ記録と照合してください。

公開phpinfoページの新設、攻撃文字列やPoCの送信、外部サイトへの脆弱性スキャンは不要です。この調査では行っていません。
