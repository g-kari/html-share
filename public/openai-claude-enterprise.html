OpenAI EnterpriseとClaude Enterpriseの比較

2〜200席を想定して、全社利用とコーディングをどう契約するか。小規模向けのBusiness／Teamも含め、席数、セキュリティ、監査、費用を人数帯ごとに比較する。

調査基準日：2026年11月18日　｜　EFS・人数別ガイド追記：2026年11月24日　｜　対象：ChatGPT Enterprise／Codex と Claude Enterprise／Claude Code

目次結論人数別の選び方比較表コード保護保持・監査Claude EFSコスト損益分岐点確認項目出典

結論：席数と、必要な監査を分けて決める

先に押さえる5点

  • 導入規模：小規模ならBusiness／Teamを比較。Claude Enterpriseの公式最低はセルフサービス20席、営業支援付き50席。OpenAI Enterpriseの価格・最低席数は要見積もり。人数別の選び方で、自社の人数と使う機能を照らし合わせる。[1][2]
  • ソースコード：両製品とも企業データを原則としてモデル学習に使わない。ただし推論に必要なコードや出力はサービスへ送られ得る。学習除外と機密情報の非送信は別の問題。[4][5]
  • 監査：ClaudeのCompliance APIはローカルClaude Codeのセッション本文を取得できるが、Claude Codeのクラウドセッションは対象外。OpenAIのCompliance Logs Platformもエージェント内の全操作を網羅するものではない。[14][15]
  • Claudeの新しいZDRオプション：一部顧客向けのEFSは、対象APIのデータを自社クラウドに保存する。提供元にコピーを残さず、自動で安全性を検査できる。適用範囲と監査の違いを確認したい。
  • 料金：Claude Enterpriseは1席月額20米ドル相当（年払い）＋全機能のトークン従量課金。30人・例示した中程度の利用量なら月額1,580米ドルという試算。OpenAI Enterpriseの総額は見積もり前には不明。[1][3]

事実以下は各社の公開仕様。判断は公開仕様からの実務上の解釈。要確認は個別契約・管理画面・試験で確かめる事項と区別する。

人数別：最初に比較するプランと、次に確かめること

以下は最初に契約予定の有料席数で選ぶ。会社の全社員数、AIの利用候補者数、毎月実際に使う人数、コード作業をする人数とは区別する。以下の区分は導入計画の目安で、公式の契約条件は各行で区別する。

2〜19席
ChatGPT Business／Claude Teamから比較する。人を絞って一般利用と開発を試し、開発者もまず標準席で計測する。業務コードを送る前に、管理者が利用者を外せるか、端末とリポジトリのログを残せるかを見る。必須要件を満たさないなら、人数が少なくてもEnterpriseの条件を照会する。
20〜49席
Claude Enterpriseのセルフサービスが候補に入る。公式の最低は20席。Business／Teamとの差は機能だけでなく料金体系にもある。Claudeの営業支援付きの公式最低は50席、OpenAI Enterpriseの最低席数と価格は要見積もり。
50〜99席
営業支援付きも見積もる。Claudeは50席以上で営業支援付き方式の候補。請求書払い・現地通貨・サポート条件が必要なら、OpenAI Enterpriseと同じ席数・部署構成で比較する。不要ならセルフサービスやBusiness／Teamも残す。
100〜150席
部門ごとに展開し、運用負荷を測る。Claude Teamは公式に150席まで。全員分を買う前に、入退社時の席の回収、監査出力、保持期間、EDRとの照合を複数部門で試す。自動アカウント管理や全社監査が必須ならEnterpriseを比較する。
151〜200席
Claudeで全員に席を出すならEnterprise。Claude Teamの上限は契約席数なので、対象が180人でも初期契約が60席なら別の判断になる。OpenAIのBusiness料金ページは従業員2〜200人を想定。課金ヘルプでは、2026年8月24日以降のBusiness契約は標準・上位合わせて最大200席（未割当も含む）。それ以前のワークスペースは以前の上限を維持する。Enterpriseの見積もりも並べる。[27]

公式条件：Claude Enterprise [1]、Claude料金 [3]、OpenAI法人向け比較 [26]。OpenAI Businessの公開料金表は従業員2人からを想定する一方、課金ヘルプには有料1席から始める記載がある。単独利用で法人ワークスペースが必要なら契約画面で最小席数を確かめる。[2][27]

全社利用と開発者用の席をどう分けるか

例えば全社員100人で、初期は一般30人・開発10人なら、比較するのはまず40席。Business／Teamの標準席でもCodex／Claude Codeを使える。上位席は、標準席では継続的に容量が足りない人を特定してから割り当てる。Claudeの現行従量型Enterpriseは単一席種で、開発も一般利用も同じ固定席単価。利用分は別料金になる。[1][3][26]

Business／Teamの席料例（米国向け公開価格、年払い）：100席を標準90席・上位10席にすると、月額換算は90×$20＋10×$100＝$2,800、年間$33,600。税・追加クレジット・APIの別課金は含まない。利用上限や機能が両社で同じという意味ではない。[3][26]

人数より先に見る条件：本番コードの送信制御、退職時の停止、監査ログの取得や保持、端末監視（EDR）が必須なら、席数や席単価より先に合格条件を決める。AIの監査だけでは端末の操作を網羅できない。逆にEDRでもクラウド上のAI操作は別証拠が必要。保持・監査の比較を見て、Git・端末・CIと突き合わせる。APIキーで動かす自動処理は、アプリの席数や料金と分けて見積もる。クレジット特典があっても、API契約・適用範囲・保持条件まで同一とは限らない。[2][12]

2. ソースコードは「学習」より送信範囲を管理する

両社のEnterprise向け文書は、業務データを既定でモデル学習に利用しないことを明示している。しかしAIがソースを参照して修正するには、必要なテキスト、ツールの応答、差分等が推論処理に渡る場合がある。認証情報や機密リポジトリのファイルを、エージェントがどこまで読めるかを制限する必要がある。[4][5]

観点Codex（OpenAI）Claude Code（Anthropic）
実行場所ローカルまたはクラウド環境。クラウド実行ではリポジトリをチェックアウトする形がある。ローカル環境で必要なファイルを参照する構成と、クラウド上の実行セッションがある。
ファイル制御サンドボックス、承認ポリシー、ネットワーク、管理設定による制限を設計する。Managed settings、ファイルのRead/Deny設定、許可済みツール等を設計する。
検査ポイントPrisma AIRS統合はCodexの新規ユーザーテキストを対象にし、ツール応答・ファイル等を網羅しない。別の仕組みと併用する。Inference hooksはユーザー入力に加えてツール結果やアップロードされたテキストの検査を支援する。
推奨運用判断機密ファイルを読み取り不可にする、トークンや秘密鍵を端末側で検出する、クラウド実行用のリポジトリ権限を分離する、外部接続先を制限する。

コード保護で確認する具体的なテスト
  1. 意図的に置いた模擬秘密情報がAIへ送られないか、禁止ファイルへのReadが拒否されるか。
  2. エージェントがネットワーク通信、パッケージ実行、外部MCP接続を開始できる条件は何か。
  3. ローカル作業とクラウド作業で、リポジトリ・作業ログ・一時ファイルの保持先がどう変わるか。
  4. ツール結果や添付からの間接的な情報流出を制御・監査できるか。

ClaudeのEFS：提供元には残さず、自社の保管先で安全性を監視

2026年11月23日・公開ベータ AnthropicのEnterprise Frontier Safeguards（EFS）は、一部の法人顧客向けに、複数のAPIリクエストにまたがる安全性の監視を追加する。従来のZDR（Zero Data Retention）は各リクエストをその場で検査する。EFSの顧客管理ストレージ方式では、入出力とモデルの推論データを顧客自身のクラウド領域に暗号化して書き込み、自動システムがそこから読み取って検査する。提供元は書き込み後に入出力のコピーを保持しない。提供元の担当者が内容を読むこともない。モデルや分類器の学習にも使わない。[22][23]

  • 適用範囲：Claude PlatformではEFSを設定したワークスペース内のMessages APIが、モデルを問わず対象。これはClaude Enterpriseの画面やClaude Code全体への標準適用を意味しない。コード実行コンテナ、Files APIのアップロード、Batch APIの結果、Managed Agentsのセッションは別の保存ルールに従う。[23]
  • 監査・EDRとの違い：顧客側は保存先の監視かSafety Cases APIの定期取得で新規ケースを把握する。ケースのJSONにはID、分類、状態、会話記録の識別子などが入り、入出力本文や抜粋は入らない。調査に必要な関連メッセージは別の読める会話記録（Transcripts）またはSafety Cases APIで確認できる。これは自社クラウドに置く暗号化済みの安全性データを直接読めるという意味ではない。EFSは端末監視（EDR）、全操作の監査、データ送信を止めるDLPの代わりにはならない。[22][23][24]
  • 契約と費用：公開ベータは対象顧客に案内される。見積もり時に、提供経路と対象ワークスペースを確認する。自社側の保存先・鍵・アクセス権・保持期間も決めておく。AnthropicのEFS利用料やモデル料金の上乗せはないが、顧客には保管、読み書き、鍵操作、該当する場合はデータ転送のクラウド費用が発生する。提供元が暗号化済みコピーを保持する方式は、顧客管理鍵を使っていてもZDRではない。[22][23]
利用規約に同意する前に：Claude Platformでは同意するとCompliance APIが有効になり、活動の記録が始まる。親組織がある場合は配下すべての組織に及び、購読プランで使うClaude CodeやCoworkの対象セッションでは本文も保存される。Access Transparency（Anthropic担当者のアクセス記録）はバケット接続開始などで作動し、一度有効になると自社では解除できない。規約への同意だけではEFSは有効にならない。既定のワークスペースは対象外で、従来のZDRから移る場合は新しいワークスペースで設定を検証してから通信を切り替える。[25]

監査で「何を証明できるか」

Claude Codeのローカルセッション取得にはユーザー入力、モデル応答、ツール呼び出しと結果が含まれる。ただしそれはAIへ送られたセッションの記録であり、端末上の最終ファイル状態やGit pushの事実を保証するものではない。OpenAI側もCompliance APIだけで実行全操作を網羅できないため、Gitの監査ログ、端末／EDR、CI、OpenTelemetry等と突き合わせる。[14][15]

データ所在地と新しいClaude機能の注意点
  • OpenAIはEnterprise向けのデータ所在地の選択肢を案内しているが、利用可能な地域・対象データ・Codexの実行場所は契約単位で確認する。[4]
  • Anthropicのネイティブ商用Claudeの保存は米国が既定。米国内での推論固定は対応モデルに対して追加料金（通常10%）を伴う。AWS等の第三者経由の地域提供とネイティブEnterpriseの所在地は同一視しない。[19][20]
  • 2026年11月に案内された統合Claude体験はクラウドのサンドボックスを使用し、ZDR／HIPAA／CMEK組織では利用条件が異なる。旧来のローカル利用と同じデータ経路だと決めつけない。[21]

トークン数で見る定額と従量の損益分岐点

Claudeの年払いを月額に換算し、1契約席あたりで比較する。Sonnet 5.5の通常料金は100万トークンあたり入力$2、出力$10。入力80％・出力20％なら、入力と出力を合わせた100万トークンで$3.60。Claude Enterpriseは「$20＋従量料金」、Claude Teamは追加クレジットを買わず席の利用枠で足りる間だけ「Standard $20／Premium $100」とする。[1][3][28]

Standard
0トークンのときだけ同額。Enterpriseの席料も$20なので、有料のトークンを使い始めるとEnterpriseの試算が上回る。Standardで追加購入したクレジットはこの比較に含めない。
Premium
月約2,222万トークン。価格差$80÷$3.60。試算どおりの入出力比なら約1,778万入力＋444万出力。交点より少なければEnterpriseの1席あたり試算が低く、多ければTeam Premiumの席料が低い。ただしTeam側の追加クレジットが不要な場合に限る。
100席の例
全員の合計で月約2億2,222万トークン。Teamは標準90席・上位10席で$2,800。Enterpriseは100席で$2,000＋従量。差額$800を埋めるのがこの量で、100席で割った平均は月約222万トークン。全員がPremiumの場合の1席交点とは別。

月額換算＝$20＋（入力100万単位×$2＋出力100万単位×$10）。モデル、入出力比、キャッシュ、追加クレジット、ツール料金、税・割引で交点は変わる。Teamの利用上限は固定トークン数ではない。OpenAI Enterpriseは固定席料の公開一律価格がなく、このグラフでは計算しない。[2][3][28]

EDR・監査・サポートを足すと、分岐点はどれだけ動くか

100席（Teamは標準90＋上位10、Enterpriseは100）の例で、D＝Teamの月間追加運用費－Enterpriseの月間追加運用費と置く。Dがプラスなら、同じ管理水準を満たすのにEnterpriseの方が運用費を抑えられる。Sonnet 5.5・入力80％の例では、損益分岐点＝（$800＋D）÷$3.60（全100席合計、月間100万トークン単位）。

たとえば月3億トークンでは、利用料込みのEnterpriseはTeamより月$280高い。同じ管理水準を満たすのにEnterpriseが月$280を超える運用費を減らせるなら、比較上の総額は逆転する。$280で同額。

  • EDR・DLP：製品やセンサーの追加契約、対象端末・仮想環境、導入運用工数の差だけを入れる。両案で同じ既存EDR費用は相殺する。Anthropicが案内する対応センサーの連携は既存製品を使い、Teamも対象。EDR本体がEnterprise席に含まれるとは見なさない。[21][29]
  • 監査・ID管理：SIEMの取り込み・保持料、監査報告の抽出、SSO・SCIMの導入と入退社対応の工数を比較する。運用工数は「月の削減時間×諸経費込みの時間単価」で換算し、設定費は比較期間に配分する。[1][26]
  • サポート・契約：OpenAIはEnterpriseで24時間365日の優先サポートやSLAを案内し、Claudeは営業支援付き契約で専任のカスタマーサクセスを案内する。実際の対象・対応時間・別料金は見積書で確認し、外部委託費や社内対応時間を本当に減らせる分だけ数える。[1][26]

同じ端末・クラウド範囲、保持期間、応答体制で比較する。必須条件を満たさない案は安くても候補外。見積もりや実測がない項目を値引き扱いせず、共通費や同じ工数を二重に数えない。

5. 人数にかかわらず契約前に確認する8項目

  1. 契約席と利用予定者：初期の有料席数、部署別の利用者、開発者数を別々に数える。最小席数、請求方法、SLA・サポートは両社で確認。
  2. 対象製品の一覧：Chat、Code、Cowork、API、クラウド実行が同一の契約・管理ポリシーで扱われるか。
  3. 送信の境界：ソース、添付、ツール結果、MCP連携内容をいつ外部へ送信するか。秘密情報遮断テストを実施できるか。
  4. 保持の一覧表：チャット、ファイル、コードセッション、API、ログ、バックアップを別々に保持期間・削除条件まで文書化できるか。
  5. ZDRと監査の両立：どの製品・機能にZDRが適用されるか。ZDR有効時にも欲しい監査証跡を取得できるか。EFSを使うなら、対象API・ワークスペース・契約経路、保存先と鍵の管理者、安全性ケースで受け取れる項目を確認する。
  6. 監査の網羅率：ローカル／クラウドで、誰が何を読み、どのコマンドを実行し、最終的に何をGitへ反映したかを突合できるか。
  7. 地域と第三者処理：データ保管・推論・外部DLP先・接続サービスの地域と再委託先を説明できるか。
  8. 上限付きの実測：小さな試用グループで2〜4週間使い、一般利用と開発を分けて、月間トークン、キャッシュ率、モデルの偏り、実際の削減工数を測る。

判断全員分を先に契約するより、初期の試用グループで「送信・保持・監査」と「1人当たりの利用量」を測ってから契約条件を比較するのが実務的。公開仕様だけではセキュリティ上の優劣や年間総費用の優劣を断定できない。
