発表の全体像

2026年11月24日、Wizは公式ブログで、OpenAIのDaybreak Defense Factoryとの連携を発表しました。Defense Factoryは、自律エージェントが脆弱性を発見し、検証し、修復する仕組みとしてOpenAIが打ち出している取り組みです。ただしコードは単独では存在しません。修復を正しく進めるには、そのワークロードがインターネットへ公開されているか、機密データへ到達できるか、高い権限と結び付いているか、といったクラウド側の文脈が要る、というのが発表の出発点です。

Wizが持ち込むのは、このクラウド文脈です。Wiz Security Graphが持つ実際のクラウド環境の情報を、Codexへ直接届けます。両社の狙いは、複雑なクラウドリスクを発生源のコードまでたどり、対象を絞ったプルリクエストの下書きを用意するところまでをエージェントに任せつつ、統制はセキュリティチームと開発チームの側に残すことです。

連携の部品は3つです。Wiz plugin for Codexが受け渡しの入口になり、CodexはWiz MCPサーバー経由でリポジトリの検出結果と文脈を取りに行きます。もう1つの経路として、検出結果をクラウド文脈とコード所有者つきでCodex Securityへ引き渡し、検証と切り分けに使うこともできます。

レイヤー図：どの層が何を持つか

役割分担を層で分けると、上が文脈、下が実行と判断です。Wiz Security Graphは、クラウドの公開状態、IDと権限、機密データといった情報を、相互の関係として保持します。検出結果だけでは分からない「攻撃者から何へ到達できるか」は、この層が持ちます。

受け渡しの層は、Wiz plugin for CodexとWiz MCPサーバーです。リポジトリにひも付く検出結果と、その背後にあるクラウド文脈をCodexへ届けます。調査と修正の層はCodexで、根元のコードをたどり、再現と修正案、プルリクエストの下書きを用意します。いちばん下の判断の層は人です。修正案をレビューし、取り込むかどうかを決めるのは、セキュリティチームと開発チームのままです。

挙動図：検出結果からPRの下書きまで

使い方の入口は自然言語です。開発者は「このリポジトリで重要なWizの検出結果を直して」のように頼みます。CodexはWiz MCPサーバー経由で、そのリポジトリの検出結果、そのコードがクラウドへ何を配備しているか、各リスクの背後にある文脈を引きます。

そのうえでCodexは、根元のコードを調査します。検出結果と、インターネットへの公開状態、クラウドのID、実効権限、機密データを突き合わせ、どのリスクが本当に重要かを見ます。公式ブログが挙げる効きどころは3つです。リスクを発生源（コード、Dockerfileの命令、IaCの定義）までたどれること、攻撃経路まで含めて全体像を把握できること、再現と対象を絞った修正とプルリクエストの準備まで進められることです。

分岐として、検出結果をCodex Securityへ引き渡す経路もあります。リポジトリの検出結果にクラウド文脈とコード所有者を付けて渡し、検証と切り分け（トリアージ）に使います。修正へ直行する前に、指摘が本物かどうかを確認する使い方です。

なぜクラウド文脈が要るのか

発表の前提は、孤立した脆弱性や設定ミスの指摘だけでは全体像が分からない、という点です。同じ深刻度の指摘でも、インターネットへ公開されていて機密データへ到達できるものと、内部に閉じていて到達経路がないものとでは、直す順番が変わります。

有効な修正には、何が公開されているか、リスク同士がどうつながっているか、攻撃者が何へ到達できるか、問題がどこで生まれたか、の4点が要ります。WizがCodexへ渡すのはこの情報で、Codexはそれを使って「なぜこの検出結果が重要か」と「どう直すか」の両方を扱います。断片的なアラートと手作業の調査から、文脈に基づく修復へ移す、というのが両社の説明です。

土台のDaybreak Defense Factory

この連携の土台は、OpenAIのDaybreak Defense Factoryです。OpenAIの公式ページでは、エージェントが脆弱性をコードの中でたどり、パッチを用意し、開発者は提案されたパッチをマージ前にレビューとテストをする、と説明されています。既存のセキュリティツールの検出結果とDaybreak Red Teamの結果を持ち込めること、Codexと直接やり取りしながら証拠の確認やパッチの調整ができること、新しいコミットのスキャンや定期チェックで継続的に回せることも、公式ページに書かれています。

Wizの連携は、この「既存ツールの検出結果を持ち込む」口の1つとして位置付けられます。違いは、検出結果に加えてWiz Security Graphのクラウド文脈まで一緒に渡る点です。WizはOpenAIのDaybreak Defense Networkのパートナーでもあり、今回の連携はその協働の一部として発表されています。Wizはこの形を、エージェント型修復（agentic remediation）を実用的で安全な、文脈に基づく進め方にするものと説明しています。

協働の実例：PHP2Shellへの対応

Wizは、この連携の土台にある協働の実例として、重大なPHP脆弱性（PHP2Shellと呼ばれるもの）への対応を紹介しています。枠組みはDaybreak Defense Networkと、その調整された取り組みであるPatch the Planetです。

流れは3段です。発見では、Wizが脆弱性を独自に発見して責任ある報告を行い、サイバーセキュリティコンサルティングのCalifがPatch the Planetを通じてOpenAIのモデルを使い、重大な欠陥を特定しました。修復では、PHPの保守者が上流の修正リリースを主導し、OpenAI、Wiz、パートナーが公開前のパッチ検証と調整を支援しました。結果として、上流パッチ、提供元側の緩和策、Wizによる脆弱性検出・悪用の監視・脅威ハンティングの案内を含む、顧客への即時の保護が出ています。

Defense Factoryは、この協働の形を大きな脆弱性対応から日常のセキュリティ運用へ広げるものだ、とWizは位置付けています。共有された情報と文脈をもとに、レビュー済みの修正へつなげる流れを、日々のリポジトリでも回す狙いです。
